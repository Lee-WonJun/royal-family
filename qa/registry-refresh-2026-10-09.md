# 등기부 목업 재조회 검수

2026-10-09 · RF-03·11·14 · SC-17·18

재조회는 필지 경계 갱신이 아니라 **등기부 목업 열람 → 이전 등기와 소유자 비교 → 변경 시 앱 알림 생성**이다. 이전 경계 재조회 HTTP 어댑터는 삭제했다. 공개 지도 좌표는 그대로 보존한다.

## 확인한 결과

- 단위·PBT: `npm run test:unit` — 37 tests, 144 assertions, 실패 0. seed 20261009, PBT 속성당 100개.
- 변경 시 이전·새 등기 ID/버전, 소유자 변경 기록, 읽지 않은 앱 알림, mock outbox가 함께 생성된다.
- 변경 없음·같은 변경본 반복·조회 실패·최초 기준 등록은 알림을 추가하지 않는다. K-GeoP 자료나 다른 PNU를 등기 기준본으로 비교하지 않는다.
- 조회 실패가 마지막 성공 등기·확인 시각을 바꾸지 않는다. 같은 idempotency key 재시도, 읽음 처리, 권한 거부, 리셋·이전 세대 차단을 검증했다.
- 조회 비용은 `charged_amount=0`이며 회계 거래가 생기지 않는다. 700원은 사용자가 제시한 참고 가정으로만 저장한다.
- 타입 검사 통과. CLJS UI·domain release 경고 0, Vinext build 통과. 기존 지도 라이브러리 청크 크기 경고는 남았다.
- 변경 UI 검사 지적 없음. 360px에서 문서 폭 345px로 가로 넘침이 없고 등기부 재조회 버튼 높이는 44px였다.

## 화면 검수의 범위

현재 앱에서 목업 결과 선택·등기부 재조회·목업 및 결제 없음 표시를 확인했다. 소유자 변경 결과는 순수 도메인 실행 결과를 별도 검수 탭의 상태 응답으로 주입해 **읽기 전용 컴포넌트 렌더링**으로 확인했다. 이전 등기 v1·새 등기 v2 원문과 `알림 2` 안의 소유자 변경 목업 알림을 열어 확인했다.

이 검수 탭은 외부 네트워크를 차단했고 재조회 명령을 실제 DB에 보내지 않았다. 화면 검수 종료 후 탭과 임시 viewport·응답 가로채기를 정리했다. 이를 저장·전달까지의 E2E나 실제 사용자에게 전송된 알림으로 기록하지 않는다.
