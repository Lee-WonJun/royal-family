# 명문가 QA 유즈케이스

작성일: 2026-10-09 · 상태: 시나리오 정의, 전체 E2E 미실행

기준은 [해커톤 PRD](../../docs/prd/hackathon-prd.md)다. UC-01–UC-08은 사용자 목표, SC-01–SC-28은 검증할 행동이다. 모든 SC의 전체 E2E 실행 상태는 **미실행**이다. 일부 단위·PBT와 [독립 UI 검수](../ui-acceptance-2026-10-09.md)는 별도로 실행했다. E2E는 [최종 게이트](../../docs/architecture/testing.md#e2e-gate) 이후에만 실행한다. 아래 기대 결과는 합격 기준이며 현재 동작을 설명한 것이 아니다.

단위·PBT·일반 E2E는 mock이 기본이다. 실제 OpenAI·ChatGPT가 필요한 기대 결과는 별도로 선택한 live 검증에만 적용한다. 일반 회귀·반응형·토글·리셋은 실제 API를 호출하지 않는다. [호출 모드와 재사용 원칙](../../docs/architecture/testing.md#modes)을 따른다.

앱 진입은 가상 계정 버튼과 권장 시나리오 선택이다. 선택한 계정은 공통 시연 관리 기능으로 이동하며 실제 본인 인증·역할별 로그인은 아니다. 관리자와 응답 대상 종원을 구분해 기록하고 역할별 권한 조합은 단위 테스트에서 주입한다.

| F-05 | 기존 회의록·사진·빠진 페이지·위임장·참석 명부·수정본. 동명이인·표기 차이·모호한 금액 포함. 준비 필요. |
| F-06 | 사용 가능한 시연 음성과 사람이 검토한 전사 대조표. 현재 rawdata에는 음성 원본이 없으므로 준비 필요. |

| F-08 | 가상 법무사·변호사 후보 각 3개 이상. 업무·지역·방식·비용 확인 여부가 다르고 필수 조건 불충족 사례 포함. 기존 파트너 페르소나를 참고하되 실제 연락처·수임 실적은 제외한다. 추천용 fixture는 준비 필요. |
| F-09 | PRD SRC-08의 공식 법령·판례와 시행/선고일·조회일·URL. 상충 규약·기준일이 다른 자료를 비교한다. 색인용 자료 준비 필요. |
| F-10 | fake clock·ID·RNG, OpenAI 성공·부분 추출·근거 없음·오류·색인 대기, 발송·callback, 기능 토글·지연 작업·리셋 입력. 가짜 비밀키만 사용하며 일반 E2E에서도 재사용. 준비 필요. |

<a id="uc-01"></a>
## UC-01 종중 설립 준비와 법무사 추천

<a id="sc-01"></a>
### SC-01 준비 업무·서류·미확정 항목 정리

- 역할: 이영수·이정호·이태식·이은지.
- 사전 조건: 준비 업무 작성 권한이 있고 등록 형태·대표자 자료는 일부 미확인이다.
- 입력: F-03·04, ‘종중 설립 준비’ 요청, 보유 서류·지역.
- 행동: 준비 건 생성 → 자료 등록 → 부족한 항목 확인 → 초안 조회.
- 기대 결과: 업무·출처·미확정 항목이 저장된다. 조직 정비·부동산등기용 등록·법인 설립 등을 한 절차로 확정하지 않는다. 모르는 값은 전문가 질문으로 남긴다.
- 연결/단계: RF-01·08·15 / 단위 테스트, 최종 mock E2E, 선택한 live 생성 결과로 품질 확인.

<a id="sc-02"></a>
### SC-02 조건에 맞는 법무사 후보 찾기

- 역할: 이영수·이정호.
- 사전 조건: 준비 업무가 정리됐고 후보는 가상 프로필이다.
- 입력: F-08, 분야·지역·원격 허용·상담 방식·예산 상한·선호 조건.
- 행동: 필터 검색 → 최대 3개 후보 비교 → 비용 미상·충족 후보 없음 조건으로 재조회.
- 기대 결과: 법무사 후보만 나오고 필수 조건과 입력 프로필을 지킨다. 비용 미상과 조건 불충족은 구분한다. 후보가 없으면 조건 조정을 안내하고 실제 제휴·예약을 주장하지 않는다.
- 연결/단계: RF-15 / PBT-10, 최종 mock E2E, 선택한 live 추천 결과 대조.

<a id="uc-02"></a>
## UC-02 회의록 STT

<a id="sc-03"></a>
### SC-03 녹음에서 검토할 회의록 만들기

- 역할: 이정호·이미경.
- 사전 조건: 일반 검증은 음성 메타데이터와 고정 전사 fixture를 준비한다. live 대표 검증에만 시연 음성·대조표·OpenAI 접근을 준비한다.
- 입력: F-06, 회의 안건·실제 참석 기록.
- 행동: 음성 등록 → 전사 → 추출 항목 확인 → 원문과 연결된 초안 조회.
- 기대 결과: 입력 파일·실행 모드·전사 결과가 남고 인명·금액·결론을 검토할 수 있다. live 대표에서는 실제 모델·호출 기록·대조 결과를 추가한다. fixture나 인터뷰 전사만으로 STT 실호출 성공을 기록하지 않는다.
- 연결/단계: RF-02·08·14 / 어댑터·상태 단위 테스트, 최종 mock E2E, live 전사 대표 사례.

<a id="sc-04"></a>
### SC-04 이름 표기 차이·흐린 사진·근거 누락

- 역할: 이태식·이정호·이미경.
- 사전 조건: 미확인 자료와 검토 권한이 있다.
- 입력: F-04·05·06의 표기 차이, 읽기 어려운 금액, 빠진 페이지.
- 행동: 등록·추출 → 원본 비교 → 수정 또는 보완 요청.
- 기대 결과: 이름만으로 사람을 병합하지 않는다. 모르는 금액·결론을 채우지 않는다. 보완본 이후에도 최초 원본·수정 이유가 남는다.
- 연결/단계: RF-02·08·09·14 / PBT-04·11, 최종 mock E2E, 선택한 live 추출 결과 확인.

<a id="sc-05"></a>
### SC-05 OpenAI·색인·외부 호출 실패

- 역할: 이정호·이도윤.
- 사전 조건: 작업 상태·중복 키가 저장되며 오류를 주입할 수 있다.
- 입력: F-10의 시간 초과·429·거부·스키마 오류·색인 대기.
- 행동: 처리 요청 → 실패/대기 확인 → 같은 요청 재시도 → 저장된 이전 결과 재사용 확인.
- 기대 결과: 실패를 성공·빈 정상 결과·문제 없음으로 바꾸지 않는다. 중복 문서를 만들지 않고 실제 호출·fake·이전 결과를 구분한다. 보완 방법을 표시한다.
- 연결/단계: RF-02·07·14 / PBT-05·11과 오류 계약 단위 테스트, 최종 mock E2E 실패 화면.

<a id="uc-03"></a>
## UC-03 기존 회의록 관리와 확인

<a id="sc-06"></a>
### SC-06 과거 회의의 원본·규약·결정 근거 찾기

- 역할: 이태식·이상훈.
- 사전 조건: 원본·보완본·당시 규약·참석 자료가 연결됐다.
- 입력: F-04·05, 당시 결정 근거에 관한 질문.
- 행동: 등록·분류 → 검색 → 인용 버전·원문·관련 토지 열기.
- 기대 결과: 당시 근거를 재현하며 원본·스캔본·보완본을 구분한다. 근거 없음과 상충을 표시하고 확인 질문을 제시한다.
- 연결/단계: RF-07·09 / PBT-04·11, 최종 mock E2E, 선택한 live 검색 결과 확인.

<a id="sc-07"></a>
### SC-07 시연 계정 선택과 자료 범위

- 역할: 이은지·이도윤·이미경.
- 사전 조건: 서버가 `demo_a` 관리자 문맥을 제공하며 `demo_b`와 제한 자료가 있다. 역할 조합은 단위 테스트용 문맥으로만 주입한다.
- 입력: F-03, 제한 연락처·문서·파일 ID·검색 범위.
- 행동: 계정별 권장 시나리오 확인 → 시연 계정 선택 → 요청의 종중·자료 ID를 바꿔 웹·MCP·검색·다운로드 접근 → 프로필에서 계정 변경.
- 기대 결과: 바로 시연 종중 관리 화면이 열린다. 요청값으로 다른 종중·신원으로 바꾸지 못하고 차단 자료가 AI 입력·검색·PDF에 남지 않는다. 종원 본인 인증을 완료했다고 표시하지 않는다.
- 연결/단계: RF-01·07·09·12 / PBT-03, 최종 mock E2E 모든 접근 경로.

<a id="uc-04"></a>
## UC-04 문서 자동작성과 운영 기록

<a id="sc-08"></a>
### SC-08 미가입자·연락 실패를 포함한 총회 준비

- 역할: 이정호·이순자·이민재.
- 사전 조건: 미가입자와 오래된 연락처가 명부에 있다.
- 입력: F-03·04·05, 안건·일정·발송 mock.
- 행동: 대상자 확정 → 안내 초안 → 모의 발송 실패 확인 → 전화 기록 → 연락처 정정.
- 기대 결과: 미가입자를 빼지 않는다. 발송·읽음·미응답·전화 안내를 구분하고 입력자·시각·근거를 남긴다. 연락처 수정이 과거 대상자·안내 이력을 바꾸지 않는다.
- 연결/단계: RF-01·05·14 / PBT-02·03·04, 최종 mock E2E 모바일·담당자 흐름.

<a id="sc-09"></a>
### SC-09 토지·계약·거래에서 결산으로 연결

필지 지도 확인(SC-09-MAP): PNU `4415011300200410001`의 실제 경계를 OSM 배경지도와 함께 표시하고 출처·확인 시각을 확인한다. 재조회는 같은 PNU의 경계만 갱신하며 다른 PNU·뒤집힌 좌표·빈 도형은 거부한다. 실패 시 기존 경계·시점을 유지하고 오류를 표시한다. 소유자·면적·시연 DB는 갱신하지 않는다. 단위·반응형 회귀는 외부 호출을 차단하고 사용자 요청의 지도·재조회 선택 사례만 별도로 확인한다. 360px·768px·PC와 확대 상태에서 버튼·자료·저작권 표시가 가려지지 않는다. [상세 계약](../../docs/architecture/parcel-map.md)을 따르며 지도 표시를 소유권 확정 또는 최신 토지 재조회로 표현하지 않는다.

- 입력: F-05·08, 질문·선택 버전·제외할 연락처.
- 행동: 준비 건 → 포함 자료·공개 범위 검토 → 저장 → 접수 mock 확인.
- 기대 결과: 선택 자료·질문만 묶이며 전체 자료실이나 다른 종원의 개인정보로 확대되지 않는다. 상태는 상담 준비/모의 접수이고 실제 전달·계약·수임 완료가 아니다.
- 연결/단계: RF-09·12·15·18 / PBT-03·05, 최종 mock E2E 공유 범위.

## 공통 화면·설정·초기화

<a id="sc-25"></a>
### SC-25 반응형 핵심 흐름과 상태 유지

- 역할: 이순자·이서연·이정호.
- 사전 조건: 필수 구현과 단위·빌드가 완료됐다. 모든 외부 어댑터는 테스트 mock이다.
- 입력: F-03·05·07·10, 360·768·1280·1440px viewport, 가로 회전·200% 확대.
- 행동: 문서 읽기·작성 → 동의 기록 → 설정 패널 열기 → 화면 크기 변경 → 입력·선택 상태 확인.
- 기대 결과: 핵심 버튼·입력·닫기가 가려지지 않고 글자·영역이 겹치지 않는다. 페이지 전체 가로 넘침 없이 표·지도는 필요한 영역만 스크롤한다. 설정을 열거나 회전해도 입력·버전·선택이 유지되고 OpenAI 호출은 0회다.
- UI 검수: CandidateUi v2의 분위기와 간결한 메뉴·상태·행동 문구를 GPT-6.1 Sol 서브에이전트가 독립 판정한다. 이 화면 검수와 전체 E2E 결과는 따로 기록한다.
- 연결/단계: RF-16·19·20 / 최종 mock E2E. 기기마다 실제 API를 다시 호출하지 않는다.

<a id="sc-26"></a>
### SC-26 시연 계정 선택·개발자 코드와 호출 토글

- 역할: 이정호·이도윤.
- 사전 조건: 시연 계정을 선택했고 초기 설정은 모든 기능 mock이다. 테스트용 코드·실제 어댑터 대역과 준비되지 않은 연결을 함께 둔다.
- 입력: F-03·10, 기능별 토글 조합·연결 준비 상태·실행 중 작업.
- 행동: 시연 계정·권장 시나리오 선택 → 톱니바퀴 → 틀린 코드·올바른 코드 확인 → 한 기능만 실제 모드 선택 → 작업 시작 → 설정 변경·계정 변경·만료 → 준비되지 않은 기능 켜기 시도.
- 기대 결과: 실제 본인 인증을 요구하지 않는다. 코드 없이는 ON 요청을 서버가 거부하며 코드 입력 안내는 개발자 직접 문의로 표시한다. 올바른 코드와 준비된 연결이 모두 있어야 선택한 기능만 실제 모드가 된다. 계정 변경·리셋·만료는 다시 잠긴다. 기존 작업은 시작 당시 모드를 유지한다. 키·코드 값은 화면에 없고 테스트의 외부 호출은 0회다.
- 연결/단계: RF-01·14·20 / PBT-12, 최종 mock E2E. 실제 연결은 별도 live 대표 사례로 확인.

<a id="sc-27"></a>
### SC-27 전체 데이터 초기화와 지연 작업 차단

- 역할: 이정호·이도윤·이상훈.
- 사전 조건: 문서·거래·동의·AI 작업·구독·outbox·토글이 초기 상태와 다르고 일부 작업은 대기 중이다. 테스트 시크릿 저장소는 별도 fake다.
- 입력: F-02–10, 초기 seed·중복 리셋 요청·이전 세대 AI/파일/이벤트 완료·초기화 실패.
- 행동: 톱니바퀴의 전체 리셋 → 중복 클릭 → 새로고침 → 이전 작업 완료 주입 → 데이터·토글·구독·화면 상태 확인.
- 기대 결과: 한 번에 초기 업무 데이터와 모든 토글의 mock 기본값으로 돌아간다. 지연 결과가 자료·알림을 복구하지 않는다. 시크릿 저장소 쓰기는 0회이고 실제 vaults·원자료·다른 종중은 대상이 아니다. 구독 재설정 필요를 표시하며 실패 시 일부 초기화를 성공으로 보이지 않는다.
- 연결/단계: RF-13·20·21 / PBT-05·12·13, 최종 mock E2E. 실제 외부 업무나 비용 취소는 검증 대상으로 삼지 않는다.

<a id="sc-28"></a>
### SC-28 종원 계층 탐색·정정·초기화

- 역할: 이정호·이은지·이도윤.
- 사전 조건: 로그인 없는 시연 관리자와 가상 명부·가계 관계가 있다. 실제 가족관계를 확인한 데이터가 아니며 외부 호출은 mock이다.
- 입력: F-03·10, 여러 세대·복수 부모·미연결 종원, 관계 정정·자기 참조·순환·다른 종중 연결, 모바일·PC 화면.
- 행동: 종원 계층 펼치기 → 상위·하위 종원과 상세 탐색 → 목록과 비교 → 관계 정정 → 잘못된 연결 시도 → 전체 리셋.
- 기대 결과: 계층·목록이 같은 종원 ID를 사용하고 미확인 관계를 임의 연결하지 않는다. 잘못된 연결을 거부하고 정정 전후 이력이 남는다. 직책·권한·과거 회의 대상은 변하지 않는다. 좁은 화면에서도 탐색할 수 있고 리셋 후 초기 명부·관계가 함께 복원된다.
- 연결/단계: RF-01·19·21·22 / PBT-03·13·14, 최종 mock E2E. 실제 API 호출은 0회다.
