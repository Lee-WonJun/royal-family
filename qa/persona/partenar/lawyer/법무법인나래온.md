# 법무법인나래온

여러 변호사와 담당 직원이 종중 재산 분쟁을 함께 검토하는 법무법인. 한 의뢰에 참여하는 사람이 많아도 담당 사건과 자료의 접근 범위를 명확하게 유지하려 한다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 외부 법무법인의 사건 담당팀 |
| 구성 | 담당 변호사 3명, 실무 직원 2명이라는 가상 설정 |
| 주된 분야 | 토지 소유권·처분 분쟁, 종중 의결과 대표권 관련 법률 검토 |
| 의뢰자 | 수임을 검토한 종중 또는 개별 당사자 |
| 주요 협업 | 사건 담당 변호사, 자료 담당 직원, 최종 의견 책임자 |
| 디지털 업무 | 자료 대조, 쟁점별 검토, 내부 검토와 의뢰인용 의견서 관리 |
| 활동 지역·상담 방식 | 서울, 전국 화상 접수 후 수행 범위와 방문 필요 확인 |
| 대표 담당자 | 책임 변호사 이재원 |
| 서비스 접근 | 법인 소속 여부와 사건 배정을 따로 관리. 배정된 건의 지정 자료만 접근 |

## 현재 행동과 불편

여러 토지와 회의가 관련된 의뢰에서는 검토자가 각각 다른 파일을 받아 의견의 기준이 어긋나기도 한다. 특정 회의의 정정본이 들어오면 누가 이전본을 검토했는지 확인해야 한다. 내부 검토 메모와 의뢰인에게 전달할 의견서도 따로 관리한다.

같은 법인으로 종중과 이의를 제기한 종중원의 상담이 들어오면 접수 단계부터 의뢰 당사자와 이해관계를 확인해야 한다. 두 요청이 같은 종중 공간에서 왔다는 이유로 자료를 합치면 안 된다. 서비스는 법인이 수임 여부를 검토하는 동안 사건 자료를 공개하지 않을 수 있어야 한다.

## 목표와 도입 조건

- 의뢰 당사자와 수임 검토 상태를 확인한 뒤 담당팀을 배정한다.
- 검토 기준이 된 자료 목록과 버전을 팀원들이 함께 확인한다.
- 내부 메모와 의뢰인에게 공개할 최종 의견을 구분한다.
- 팀 변경과 검토 책임자 승인 내역을 남긴다.

법인 소속 전원에게 사건 자료를 공개하거나 내부 메모를 자동 전달하는 서비스는 도입하지 않는다.

대표 발언: “같은 법인 계정이라고 모든 사건을 열어주면 곤란합니다. 담당팀이 검토한 자료와 최종 의견의 기준을 확인할 수 있어야 합니다.”

## 서비스 사용 장면

종중이 토지 처분 기록 검토를 의뢰한다. 접수 담당자는 의뢰 당사자와 관련 당사자 정보를 받아 수임 검토를 진행한다. 수임 후 지정 팀원이 허용된 자료를 검토하고, 책임 변호사가 확인한 의견을 의뢰인에게 전달한다. 새 자료가 추가되면 검토 대상 버전을 갱신하고 재검토할 항목을 남긴다.

다른 당사자의 요청은 별도로 접수한다. 수임 여부와 공개 범위를 결정하기 전까지 기존 사건 자료나 내부 의견을 공유하지 않는다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 팀 배정 | 같은 법인 소속이라도 미배정 직원은 의뢰 자료를 열 수 없다. |
| 수임 검토 | 관련 당사자의 별도 의뢰가 기존 사건과 자동 병합되지 않는다. |
| 의견 공개 | 내부 검토 메모와 승인된 의뢰인용 의견서의 공개 범위가 다르다. |
| 검토 자료 변경 | 새 자료가 들어오면 기존 의견의 검토 기준과 재검토 상태를 확인할 수 있다. |

## PRD 연결

P1 전문가 공유를 조직의 담당팀 단위로 검증한다. 수임 검토, 팀 배정과 내부 의견 관리의 구체적인 제공 범위는 전문가 인터뷰로 확인할 확장 요구다. 현재 구현된 사건 관리 기능으로 제시하지 않는다.

근거 문서: [PRD 초안](../../../../rawdata/TTS/03_PRD_초안.md)의 사용자와 권한, 전문가 의뢰, 기록 보호와 운영 요구.

현재 기획: [해커톤 PRD](../../../../docs/prd/hackathon-prd.md)의 [RF-09](../../../../docs/prd/hackathon-prd.md#rf-09), [RF-18](../../../../docs/prd/hackathon-prd.md#rf-18). P0·P1은 통화 기반 초안 단계의 구분이며, 현재 범위는 해커톤 PRD에서 확인한다. 페르소나를 실제 수임·제휴나 기능 구현 완료의 근거로 사용하지 않는다.
