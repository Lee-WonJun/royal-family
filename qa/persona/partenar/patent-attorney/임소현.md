# 임소현

소프트웨어 기술 설명을 검토하는 개인 변리사. 기능 소개와 실제 기술 자료를 구분해 필요한 설명을 요청하고, 기술의 공개 범위를 의뢰인과 확인한다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 개인 변리사 |
| 나이와 경력 | 35세, 소프트웨어 관련 지식재산 업무 6년 |
| 활동 지역·상담 방식 | 대전·서울, 화상 상담과 기술 문서 검토 |
| 주된 분야 | 소프트웨어 기술 관련 특허 상담·출원 준비 |
| 의뢰자 | 서비스 운영사의 개발·제품 담당자 |
| 의뢰 조건 | 기술 내용·공개 상태·상담 목적을 먼저 확인 |
| 디지털 업무 | 기술 문서의 버전과 추가 질문을 관리 |
| 서비스 접근 | 공유가 승인된 기술 자료만 접근 |

## 현재 행동과 불편

제품 소개 자료만 보내고 특허가 가능한지 바로 답해달라는 문의가 들어온다. 자료가 부족해 실제 처리 방법을 다시 질문해야 한다. 예시 데이터에 종중원 정보와 API 키가 섞여 있으면 기술 검토에 필요한 범위로 다시 정리하도록 요청한다.

## 목표와 도입 조건

- 기능 설명과 구체적인 기술 자료를 구분한다.
- 자료의 공개 상태와 검토에 사용할 버전을 확인한다.
- 예시 데이터는 신원 정보와 운영 비밀을 제외한 형태로 받는다.

미확인 기술을 AI가 설명으로 채우거나 검토 자료가 승인 없이 다른 의뢰에 재사용되는 서비스에는 자료를 올리지 않는다.

대표 발언: “기능 소개만으로 기술을 판단하기는 어려워요. 실제로 어떻게 처리하는지 설명한 자료가 필요합니다.”

## 서비스 사용 장면

개발 담당자가 문서 처리 기능의 검토를 요청한다. 임소현은 기술 설명과 현재 공개된 범위를 확인한다. 필요한 질문을 남기고 검토 버전을 고정한다. 고객의 실제 명부나 운영 키는 기술 설명을 위한 입력에서 제외한다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 기술 정보 부족 | 제품 설명만 있으면 기술 내용을 추측하지 않고 보완 질문을 남긴다. |
| 민감 자료 | 기술 의뢰에 불필요한 명부·키를 기본 전달 자료로 포함하지 않는다. |
| 버전과 공개 | 검토 자료의 버전과 의뢰인이 설명한 공개 상태를 구분해 기록한다. |

## PRD 연결

기술 자료를 다루는 변리사 확장 후보로 문서 버전·출처·제한된 공유를 검증한다. 특허 지원은 현재 해커톤의 확정 기능으로 간주하지 않는다. 현재 기능의 구현이나 실제 외부 접수 완료를 뜻하지 않는다.
