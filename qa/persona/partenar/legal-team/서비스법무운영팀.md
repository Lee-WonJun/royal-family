# 서비스법무운영팀

서비스 운영사에서 전문가 연계와 법률 검토 과제를 관리하는 팀. 고객 문의를 업무별로 분류하고, 제품의 안내·서식·상태 표시가 실제 검토와 처리 범위를 설명하는지 확인한다.

단체명·인원·업무 경험과 대표 발언은 QA를 위한 가상 설정이다. 실제 회사의 조직이나 운영 실적을 뜻하지 않는다. 서비스 운영 측의 검증 관점을 외부 전문가·종중 담당팀과 구분한다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 서비스 운영사의 법무·전문가 연계 담당팀 |
| 구성 | 법률 검토 담당 변호사, 파트너 운영 담당자, 제품 담당자 등 3명이라는 가상 설정 |
| 주된 업무 | 업무 분류 기준, 전문가 자격·담당 범위 확인, 서식과 제품 안내 검토 |
| 협업 대상 | 종중 구성·등록 지원자, 토지 담당 변호사·법무사, 지식재산 담당 변리사 |
| 디지털 업무 | 익명화된 사례 검토, 안내 버전 관리, 연계 오류와 미결 과제 추적 |
| 서비스 접근 | 업무상 필요한 정보만 접근. 운영팀 소속이라는 이유로 고객의 전체 의뢰 자료를 열람하지 않음 |

## 현재 행동과 불편

사용자가 ‘종중 설립’이나 ‘땅 문제’라고만 문의하면 담당 전문가를 정하기 어렵다. 창구에서 잘못 분류한 의뢰가 전달되면 자료를 다시 요청해야 한다. 운영 담당자가 파일 준비를 도왔다는 이유로 신청이 완료됐다고 안내하는 것도 막아야 한다.

전문가가 검토한 서식과 제품에 반영된 서식의 버전이 다르면 어느 기준을 사용했는지 찾기 어렵다. 새 기능을 기획할 때에는 확인이 필요한 법률 쟁점과 이미 정한 제품 요구를 분리해서 관리하고 싶다.

## 목표와 도입 조건

- 문의 목적과 의뢰 주체를 먼저 확인해 적합한 분야로 연결한다.
- 전문가별 담당 가능 업무와 미확인 범위를 확인 상태와 함께 관리한다.
- 서식·도움말의 검토자, 적용 버전과 변경 사유를 남긴다.
- 자료 준비, 전문가 검토, 외부 접수와 완료 증빙을 다른 상태로 표시한다.

대표 발언: “문의에 ‘땅’이 들어갔다고 같은 전문가에게 보내면 안 돼요. 등기 신청인지, 분쟁 상담인지, 종중의 운영 정비인지 먼저 확인해야 합니다.”

## 서비스 사용 장면

운영팀은 익명화된 문의 예시로 분야 선택 화면을 검토한다. 토지 소유권 분쟁은 [변호사](../lawyer/박지훈.md), 토지 등기 서류는 [법무사](../judicial-scrivener/정수민.md), 종중 구성·규약·등록 정비는 [초기 지원 담당자](../clan-setup/한지우.md)에게 연결할 질문을 정리한다. 서비스 이름·기술의 권리에 관한 문의는 [변리사](../patent-attorney/최유진.md) 분야로 구분한다.

이 분류는 상담을 시작하기 위한 기준이다. 실제 수임과 수행 가능 범위는 담당 전문가가 확인한다. 고객 자료가 필요하면 요청 목적과 승인된 열람 범위를 확인하고, 운영팀 전체에 공유하지 않는다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 모호한 의뢰 | 목적이 불명확하면 추가 질문을 남기고 자격명만으로 자동 배정하지 않는다. |
| 서식 변경 | 검토된 서식과 제품에 적용된 버전을 확인하고 미검토 변경을 구분한다. |
| 처리 상태 | 서류 준비나 상담 완료를 외부 접수·등기 완료로 안내하지 않는다. |
| 운영 접근 | 분야 분류와 운영 확인에 불필요한 명부·사건 자료는 열람할 수 없다. |

## PRD 연결

P0 출시 전의 법률 검토 경계와 P1 전문가 연계의 운영 조건을 검증한다. 개인정보 처리 기준, 전문가와 서비스의 책임 범위, 비용과 실제 연계 방식은 확정할 과제로 남긴다. 이 페르소나는 팀 구성이나 기능 구현이 완료됐다는 뜻이 아니다.

근거 문서: [PRD 초안](../../../../rawdata/TTS/03_PRD_초안.md)의 다음 출시 범위, 기록 보호와 운영 요구, 법률 검토가 필요한 경계, 초안을 확정하기 위한 질문.
