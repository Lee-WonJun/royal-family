# 잇다파트너검토팀

서비스에 표시할 전문가 후보 정보를 확인하는 운영팀. 실제 확인한 정보와 페르소나용 조건을 구분하고 문의가 잘못 배정되는 이유를 점검한다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 서비스 운영사의 파트너 후보 검토팀 |
| 구성 | 법률 검토 담당자 1명, 후보 정보 운영 담당자 2명 |
| 활동 지역·협업 방식 | 온라인 운영, 전문가 정보 확인은 별도 절차 |
| 주된 업무 | 후보 분야·지역·상담 방식·확인 상태 관리 |
| 대표 담당자 | 후보 정보 담당 장채원 |
| 협업 대상 | 변호사·법무사·변리사 후보와 초기 지원 담당자 |
| 디지털 업무 | 후보 정보 버전과 추천 제외 사유 기록 |
| 서비스 접근 | 후보 정보와 필요한 문의 분류 정보만 접근 |

## 현재 행동과 불편

활동 지역이 넓다고 적혀 있어도 모든 업무를 맡을 수 있는 것은 아니다. 후보 정보가 오래됐거나 상담 방식이 바뀌면 추천 설명이 실제 조건과 어긋난다. 시연용 전문가를 등록된 제휴 전문가처럼 보여주면 사용자가 실제 예약이 가능한 것으로 오해한다.

## 목표와 도입 조건

- 후보 정보의 출처·확인 시점·미확인 항목을 관리한다.
- 추천 조건과 제외 사유를 사용자에게 설명한다.
- 가상 후보와 실제 확인된 제휴·수임 상태를 다른 값으로 유지한다.

인기·승소율·실제 수임 가능성을 임의로 채우거나 후보 검토에 고객의 전체 사건 문서를 요구하는 방식은 받아들이지 않는다.

대표 발언: “조건이 비어 있으면 빈 채로 보여줘야 해요. 가상 후보를 실제 예약 가능한 전문가처럼 안내하면 안 됩니다.”

## 서비스 사용 장면

장채원이 후보 정보의 변경 내역을 검토한다. 지역은 맞지만 업무 분야나 상담 방식이 맞지 않는 후보를 추천에서 제외하고 이유를 남긴다. 시연에서는 모든 후보가 페르소나임을 유지하며 실제 계약이나 접수 상태를 만들어 넣지 않는다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 조건 필터 | 지역만 맞는 후보가 업무·상담 조건 불일치를 무시하고 우선 추천되지 않는다. |
| 미확인 정보 | 빈 조건과 오래된 정보가 확인된 사실이나 확정 수임 가능으로 바뀌지 않는다. |
| 가상 상태 | 페르소나 후보와 실제 검증·제휴·예약 상태를 구분한다. |

## PRD 연결

법무사·변호사 추천의 조건 필터와 설명을 검증한다. 변리사는 현재 추천 범위를 확장할 때 별도로 확인할 대상이다. 현재 기능의 구현이나 실제 외부 접수 완료를 뜻하지 않는다.
