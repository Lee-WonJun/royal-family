# 솔빛문중법무팀

종중 안에서 서류를 모으고 외부 전문가와 연락하는 업무 담당팀. 법률 자격을 전제로 하지 않는 내부 조직이며, 자료 준비와 전문가의 판단을 구분해 전달한다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 종중 내부의 업무 담당팀 |
| 구성 | 총무, 서류 보관 담당자, 전문가 연락 담당자 등 3명이라는 가상 설정 |
| 주된 업무 | 토지·회의 서류 준비, 상담 접수, 보완 자료 수집과 결과 전달 |
| 관련 종중원 | 회장 [이영수](../../familly/이영수.md), 총무 [이정호](../../familly/이정호.md), 기록 검토자 [이미경](../../familly/이미경.md) |
| 법률 전문성 | 팀 구성원에게 변호사·법무사 자격이 있다고 가정하지 않음 |
| 디지털 업무 | 문서 묶음 준비, 공유 승인 요청, 전문가와의 요청·답변 정리 |
| 활동 지역·협업 방식 | 경북, 전화·대면으로 자료 수집 후 온라인 의뢰 정리 |
| 대표 담당자 | 전문가 연락 담당 이승재 |
| 서비스 접근 | 부여된 자료 준비·공유 업무만 수행. 팀 명칭만으로 전체 권한을 얻지 않음 |

## 현재 행동과 불편

전문가가 요청한 자료를 회장과 전임 담당자에게 각각 받아야 한다. 어떤 규약과 회의록이 현재 검토 대상인지 확인하지 못하면 다시 전달하는 일이 생긴다. 전문가 답변을 전화로 받아 전달하면 원래 설명과 종중 내부의 해석이 섞이기도 한다.

‘법무팀이 확인했다’는 표현을 법률 검토가 끝났다는 뜻으로 받아들이는 종중원도 있다. 팀은 자신들이 준비한 자료, 전문가가 검토한 내용과 추가 확인 사항을 구분해 보여주고 싶다.

## 목표와 도입 조건

- 의뢰 목적에 맞는 전문가를 찾고 요청 자료를 준비한다.
- 자료 공유를 승인할 사람과 실제 공유한 범위를 기록한다.
- 전문가의 원문 의견, 팀의 업무 메모와 미해결 질문을 구분한다.
- 담당자가 바뀌어도 자료 요청·답변과 공유 기한을 이어받는다.

팀 명칭만으로 대표권을 부여하거나 내부 자료 확인을 법률 판단으로 안내하는 서비스는 사용하지 않는다.

대표 발언: “우리가 서류를 모았다는 표시와 전문가가 검토했다는 표시를 나눠주세요. 다음 담당자도 무엇을 더 확인해야 하는지 알아야 합니다.”

## 서비스 사용 장면

토지 등기 관련 준비 업무가 생기면 팀이 목적과 보유 자료를 정리한다. 법무사에게 자료를 공유하기 전에 권한 있는 담당자의 승인을 확인한다. 누락 서류를 추가하고 요청·답변을 의뢰 건에 남긴다. 대표자나 의결에 관한 이견이 있으면 별도의 법률 검토 항목으로 기록해 변호사에게 문의한다.

회신을 받은 뒤에는 전문가 의견을 원문과 함께 전달한다. 자료 정리 완료, 전문 검토 완료와 실제 신청 완료를 별도로 표시한다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 팀 권한 | 팀 이름이나 총무 직책만으로 전체 명부·의뢰 자료 접근과 공유 권한을 얻지 않는다. |
| 외부 공유 | 승인자, 공유 문서와 기한을 확인하고 불필요한 종중원 정보를 제외한다. |
| 검토 결과 전달 | 내부 자료 확인과 전문가의 법률 검토를 다른 상태와 작성자로 표시한다. |
| 인수인계 | 진행 중인 보완 요청과 미해결 질문을 이어받고 전임자의 권한을 조정한다. |

## PRD 연결

P0의 문서 보관·권한·인수인계와 P1의 전문가 의뢰를 연결해 검증한다. 내부 담당팀은 외부 전문 자격이나 종중 대표권을 대신하지 않는다. 구체적인 승인 담당자는 종중별 운영 기준으로 확인한다.

근거 문서: [PRD 초안](../../../../rawdata/TTS/03_PRD_초안.md)의 사용자와 권한, 주요 사용 흐름, 전문가 의뢰, 법률 검토가 필요한 경계.

현재 기획: [해커톤 PRD](../../../../docs/prd/hackathon-prd.md)의 [RF-09](../../../../docs/prd/hackathon-prd.md#rf-09), [RF-10](../../../../docs/prd/hackathon-prd.md#rf-10), [RF-15](../../../../docs/prd/hackathon-prd.md#rf-15). P0·P1은 통화 기반 초안 단계의 구분이며, 현재 범위는 해커톤 PRD에서 확인한다. 페르소나를 실제 수임·제휴나 기능 구현 완료의 근거로 사용하지 않는다.
