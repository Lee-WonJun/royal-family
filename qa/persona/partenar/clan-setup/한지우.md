# 한지우

종중의 구성·규약·대표자와 등록 체계를 정리하도록 돕는 개인 변호사. ‘종중을 설립하고 싶다’는 요청을 받아 실제 필요한 자문과 신청 업무로 나눈다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

| 서비스 접근 | 초기 정비 의뢰에 필요한 자료만 접근. 정비 완료 후 운영 권한은 별도 부여 |

## 현재 행동과 불편

의뢰인이 ‘설립’이라고 말해도 기존 종중의 서류 정비, 대표자 선임 관련 검토, 등록번호 업무, 토지 등기 또는 별도의 단체 구성 중 무엇을 원하는지 다를 수 있다. 자료가 거의 없을 때는 누가 관계자이고 어떤 재산을 관리해왔는지부터 질문해야 한다.

공통 규약 양식을 채웠다는 이유로 모든 법적 요건과 신청이 끝났다고 생각하면 후속 업무를 설명하기 어렵다. 준비 모임에서 말한 구성원 목록과 검토를 거친 명부도 구분해서 보관해야 한다.

## 목표와 확인 순서

1. 의뢰 목적, 기존 조직과 자료, 공동선조·활동·재산 관련 설명을 확인한다.
2. 검토할 단체의 형태와 구성원·대표자 관련 쟁점을 정리한다.
3. 규약, 회의 준비와 필요한 확인 자료를 업무에 맞춰 검토한다.
4. 등록번호, 세무상 등록, 부동산 등기 등 추가 업무를 구분하고 적합한 담당자에게 연결한다.
5. 정비한 자료를 종중 운영 공간으로 넘기되 자문 완료와 실제 신청 완료를 따로 기록한다.

종중 구성·운영 정비·등록·토지 등기를 하나의 설립 완료로 묶는 서비스는 도입하지 않는다.

대표 발언: “‘설립’이라고 부르는 일을 먼저 나눠보죠. 이미 있는 종중의 운영을 정리하는지, 별도의 단체를 만드는지에 따라 준비가 달라집니다.”

## 서비스 사용 장면

이영수가 초기 정비 상담을 신청한다. 한지우는 기존 규약·회의록·등록 자료의 유무와 확인 상태를 살피고, 명부나 대표자 정보에 이견이 있으면 검토 항목으로 남긴다. 이정호가 자료를 준비하면 확인한 버전과 후속 업무 목록을 전달한다. 이후 토지 등기 업무가 필요하면 법무사와 공유할 자료를 별도로 지정한다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 신규 정비 상담 | ‘종중 설립’ 버튼 하나로 법인 설립·단체 등록·토지 등기를 동일 처리하지 않는다. |
| 기초 자료 부족 | 확인하지 않은 관계자·대표자 정보를 확정하지 않고 필요한 질문과 자료를 남긴다. |
| 업무 분리 | 자문 검토, 운영 자료 준비, 외부 신청과 실제 완료를 다른 단계로 추적한다. |
| 운영 이관 | 검토된 규약·명부의 버전과 미해결 쟁점이 이후 운영 담당자에게 전달된다. |

## PRD 연결

PRD의 ‘온라인 신청 업무 유형을 먼저 확인한다’는 요구를 초기 구성·등록 정비에 적용한다. 구체적인 초기 지원 상품과 절차는 PRD 확장 후보이며 현재 구현 상태를 뜻하지 않는다.

근거 문서: [PRD 초안](../../../../rawdata/TTS/03_PRD_초안.md)의 종중 공간과 구성원 관리, 다음 출시 범위, 초안을 확정하기 위한 질문.

설계 참고: 고유 종중과 통합 단체의 성격을 구분한 [대법원 2008다41567 판결](https://www.law.go.kr/LSW/precInfoP.do?precSeq=64708)을 참고해 의뢰 대상의 성격을 먼저 검토하는 흐름으로 설정했다. 해당 판결의 특정 사건 결과를 다른 의뢰에 적용하는 설정은 아니다.

현재 기획: [해커톤 PRD](../../../../docs/prd/hackathon-prd.md)의 [RF-15](../../../../docs/prd/hackathon-prd.md#rf-15), [RF-17](../../../../docs/prd/hackathon-prd.md#rf-17). P0·P1은 통화 기반 초안 단계의 구분이며, 현재 범위는 해커톤 PRD에서 확인한다. 페르소나를 실제 수임·제휴나 기능 구현 완료의 근거로 사용하지 않는다.
