# 류지석

구성원 범위와 대표자 관련 이견을 정리하는 개인 변호사. 초기 운영 체계를 준비할 때 관계 자료와 참여자의 설명을 받아 검토할 쟁점을 남긴다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 개인 변호사 |
| 나이와 경력 | 56세, 단체 분쟁·운영 자문 23년 |
| 활동 지역·상담 방식 | 전국 화상 상담, 필요한 자료 확인은 대면 협의 |
| 주된 분야 | 구성원·대표자 관련 쟁점과 초기 운영 기준 검토 |
| 의뢰 조건 | 관계 자료의 출처와 당사자 설명, 의뢰 주체 확인 |
| 디지털 업무 | 서로 다른 명부·규약의 출처와 확인 상태 비교 |
| 서비스 접근 | 검토 범위의 관계 자료에 제한된 접근 |

## 현재 행동과 불편

연락 가능한 사람만 모은 명부를 전체 종중원 목록이라고 전달받는다. 앱 가입자가 자격이 확인된 구성원이라고 기대하는 사람도 있다. 족보 자료와 다른 명부가 어긋나면 왜 다른지 질문해야 하며 개인정보가 많은 원문을 무조건 팀 전체에 공유하고 싶지 않다.

## 목표와 도입 조건

- 연락 대상 명부와 자격·범위 검토 자료를 구분한다.
- 명부별 출처와 이견, 추가 확인 사항을 기록한다.
- 관계 자료의 공유 대상을 의뢰 목적에 맞게 제한한다.

계정 가입·성별·자동 관계 추출만으로 구성원 자격이나 의결권을 판정하는 흐름에는 동의하지 않는다.

대표 발언: “앱에 들어온 사람 목록만으로 구성원 범위를 정할 수는 없습니다. 자료의 출처와 다른 의견을 같이 확인해야 해요.”

## 서비스 사용 장면

초기 준비 모임이 여러 명부를 올린다. 류지석은 등록자와 출처를 확인해 목록 간 차이를 정리한다. 새 참여자 [이은지](../../familly/이은지.md)의 계정 연결과 구성원 관련 검토는 별도 상태로 유지한다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 자격 구분 | 계정 가입·연락처 등록이 구성원 자격 확정으로 바뀌지 않는다. |
| 명부 대조 | 상이한 명부의 출처·버전과 미해결 차이가 유지된다. |
| 민감 공유 | 검토에 필요한 관계 자료만 지정 전문가에게 공유된다. |

## PRD 연결

초기 명부·권한 구성과 법률 검토의 경계를 검증한다. 구성원 자격을 자동으로 확정하는 규칙을 만들기 위한 페르소나는 아니다. 현재 기능의 구현이나 실제 외부 접수 완료를 뜻하지 않는다.

현재 기획: [해커톤 PRD](../../../../docs/prd/hackathon-prd.md)의 [RF-01](../../../../docs/prd/hackathon-prd.md#rf-01), [RF-15](../../../../docs/prd/hackathon-prd.md#rf-15), [RF-17](../../../../docs/prd/hackathon-prd.md#rf-17).

배경 자료: [통화 기반 PRD 초안](../../../../rawdata/TTS/03_PRD_초안.md). 이 문서의 P0·P1은 원자료 단계의 구분이다.
