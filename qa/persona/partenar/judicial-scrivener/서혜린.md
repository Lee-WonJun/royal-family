# 서혜린

전자 문서로 토지 등기 관련 준비 자료를 받는 개인 법무사. 반복 입력을 줄이되 자동 추출값을 신청 자료에 쓰기 전 직접 확인한다.

이름·단체명·나이·경력·구성·지역·경험과 대표 발언은 모두 페르소나를 위한 가상 설정이다. 실제 전문가의 신원·자격·수임 가능성이나 실제 제휴를 나타내지 않는다.

## 기본 설정

| 항목 | 내용 |
| --- | --- |
| 형태 | 개인 법무사 |
| 나이와 경력 | 36세, 등기 관련 업무 7년 |
| 활동 지역·상담 방식 | 서울·경기, 화상 상담과 전자 자료 접수 |
| 주된 분야 | 토지 등기 신청 서류 준비와 보완 관리 |
| 의뢰 조건 | 요청 업무·위임 관계·발급 자료의 시점 확인 |
| 디지털 업무 | PC에서 원문과 추출값을 대조하고 보완 목록 관리 |
| 서비스 접근 | 선택한 의뢰의 자료와 검토할 문서 버전 |

## 현재 행동과 불편

AI가 읽은 지번이나 이름을 의뢰인이 확정값으로 전달하면 원문과 다시 대조해야 한다. 문서 검토 중 총무가 파일을 바꾸면 어떤 내용에 확인 표시를 했는지도 헷갈린다. 발급일이 다른 자료를 최신본이라고 묶어 보내는 경우도 있다.

## 목표와 도입 조건

- 자동 추출값 옆에서 원문 위치와 미확인 표시를 확인한다.
- 검토한 버전에만 확인 표시를 남기고 수정본은 다시 확인한다.
- 추가 자료 요청과 수신 상태를 한 의뢰에서 추적한다.

검토할 파일이 바뀌어도 이전 확인 표시가 그대로 유지되는 서비스는 신청 준비에 쓰기 어렵다.

대표 발언: “입력을 줄여주는 건 좋아요. 대신 제가 확인한 값과 AI가 읽기만 한 값은 구분돼야 합니다.”

## 서비스 사용 장면

[이정호](../../familly/이정호.md)가 스캔 서류를 올린다. 서혜린은 지번과 명칭을 원문과 비교해 확인하고 빠진 자료를 요청한다. 총무가 수정본을 올리면 기존 확인을 이어 쓰지 않고 변경 부분을 재검토한다.

## 검증 시나리오

| 상황 | 관찰할 행동과 통과 기준 |
| --- | --- |
| 자동 추출 | 불명확한 인명·지번은 미확인으로 남고 원문 위치를 열 수 있다. |
| 버전 변경 | 수정된 문서는 재검토가 필요하며 이전 검토 버전이 유지된다. |
| 자료 시점 | 발급일·등록일·검토일이 구분되어 오래된 자료를 식별할 수 있다. |

## PRD 연결

문서 추출·버전 검토와 법무사 후보의 디지털 상담 조건을 함께 검증한다. 현재 기능의 구현이나 실제 외부 접수 완료를 뜻하지 않는다.

현재 기획: [해커톤 PRD](../../../../docs/prd/hackathon-prd.md)의 [RF-02](../../../../docs/prd/hackathon-prd.md#rf-02), [RF-08](../../../../docs/prd/hackathon-prd.md#rf-08), [RF-15](../../../../docs/prd/hackathon-prd.md#rf-15).

배경 자료: [통화 기반 PRD 초안](../../../../rawdata/TTS/03_PRD_초안.md). 이 문서의 P0·P1은 원자료 단계의 구분이다.
