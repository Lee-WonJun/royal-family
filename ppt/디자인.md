# 명문가 발표자료 디자인

## 기준

첫 초안의 종이색 배경과 깊은 청록을 기본으로 쓴다. 사용자가 v5에서 되돌린 도입부와 명문가 소개 화면을 기준으로 삼는다. 푸른 기운은 낮은 채도의 청록과 회청색으로 표현한다. v16은 리뷰 다음에 사용자 제공 개선 피드백·작업 지시 캡처를 겹친 한 장을 추가한 32장 자료다.

`Premium Cloud Widescreen Multicolored.pptx`는 픽토그램과 다이어그램의 참고 자료다. 원 안의 아이콘, 단계 연결, 포함 관계를 빌려 쓰되 템플릿의 무지개색과 회색 글씨를 전체 테마로 가져오지 않는다.

발표자가 설명한다. 슬라이드는 문장을 대신 읽어주는 화면보다 사진, 큰 숫자, 관계를 보여주는 그림에 가깝게 만든다.

## 발표와 IR의 리듬

발표는 **가운데 전화 모양 재생 버튼**으로 시작한다. 첫 장에는 제목이나 보조 문구를 넣지 않는다. 개인 경험, 제품 기능, 시장 추정 뒤에 Codex 활용 파트를 둔다. **Codex 요약은 이 파트의 첫 페이지**다. 통화 전사, PRD, 페르소나, 법령·판례·필지 자료 수집, UI·코드·배포, 테스트·UI 검수를 여섯 개 원형 픽토그램으로 연결한다. PRD와 페르소나는 별도 항목이며, 중심에는 실제 설치된 Codex 앱 아이콘을 쓴다.

Codex 뒤에는 실제 코드 기반 서비스 아키텍처, AI 모델과 검색 기술, 안전한 SW를 만드는 방식을 둔다. **One More Thing 직전의 리뷰 페이지 제목은 ‘AI도 인정하는 부분’**이다. 사용자 제공 리뷰 6개를 **3열·2행 카드**에 담고, SUIT의 가벼운 본문·선명한 별점·아래쪽 이름으로 위계를 나눈다. 문장과 점수는 그대로 유지한다. 평균 4.5는 여섯 점수의 단순 평균이다. 흰 카드, 작은 모서리 곡률과 얇은 테두리를 쓴다. **Skills·MCP·MCP Events는 One More Thing 뒤 ‘For Agents’에 모은다.** 이어 사용자 제공 ChatGPT 로그인 화면을 원본 그대로 보여준다. 마지막은 명문가 브랜드 페이지다. 별도의 `지금 / 다음` 장은 만들지 않는다.

리뷰 바로 다음 장은 기존 리뷰 페이지를 고해상도 배경으로 그대로 둔다. 밝은 반투명 레이어로 배경을 낮추고, 사용자 제공 개선 피드백 캡처와 후속 작업 지시 캡처를 원본 비율로 겹쳐 놓는다. 두 캡처에 약한 그림자를 주고 아래 캡처를 오른쪽으로 조금 옮긴다. 설명·제목·화살표 등 새 문구나 표시는 추가하지 않는다. 원래 리뷰 페이지는 편집 가능한 상태로 유지하고, 이 전환 장면에서는 사진 세 장을 각각 교체할 수 있게 한다.

내용 화면은 왼쪽 정렬을 기본으로 쓴다. 질문, 실패 경험, 브랜드 공개, One More Thing에는 넓은 여백과 큰 글자를 쓴다. 같은 크기의 아이콘 원이나 카드 세 개를 매 장 반복하지 않는다. 하단의 두꺼운 회색 띠와 제작용 문구는 빼고 쪽수만 남긴다. 출처와 상세 조건은 발표자 노트에 둔다.

밝은 종이색과 짙은 청록 사이의 전환으로 장면을 구분한다. 기능 소개에는 푸른 청록 `#173F49`, 옅은 회청색 `#E2ECEE`를 사용할 수 있다. 화려한 그라데이션, 3D 장식, 의미 없는 강조색은 쓰지 않는다.

| 회청색 | `#567D89` | 비교 대상, SAM, 보조 아이콘 |

| 녹회색 | `#687568` | 출처, 날짜, 작은 설명 |

밝은 배경에서는 청록을 주로 쓰고 비교가 필요한 요소만 보조색으로 구분한다. 한 화면에서 비슷한 의미의 요소에 다른 색을 임의로 붙이지 않는다. 사용자가 직접 고른 강조색과 사진 속 색은 유지한다.

## 글자와 문구

- 본문은 **Pretendard Regular**, 큰 제목과 숫자는 **Pretendard Bold**를 쓴다. 한글과 숫자의 굵기와 비례를 맞춘다. 작은 설명까지 모두 두껍게 만들지 않는다. 명문가 브랜드명에만 **Noto Serif KR**를 쓴다. 기존 Noto Sans KR·Calibri Light 조합은 사용하지 않는다.
- 리뷰 페이지는 **SUIT Regular·SemiBold·Bold**로 구성한다. 역할 설명은 작게, 이름과 점수는 분명하게 두며 인용문 전체를 굵게 만들지 않는다. [SUIT 공식 배포](https://github.com/sun-typeface/SUIT)의 폰트와 OFL 라이선스를 함께 보관한다.
- 16:9 화면을 유지한다. 현재 PPT의 실제 크기는 10 × 5.625인치다.
- 일반 제목은 30~36pt, 기능 화면의 큰 문구는 38~47pt, 항목 이름은 18~24pt, 큰 수치는 60~100pt를 기준으로 잡는다. 슬라이드 크기는 유지하고 글자가 넘치면 문구나 배치를 먼저 고친다.
- 한 화면에서 전달할 내용은 하나로 정한다. 짧은 제목, 필요한 항목 이름, 숫자만 먼저 남긴다.
- `회의 녹음`, `동의 요청`, `재산 자료 비교`처럼 화면에 있는 일을 직접 쓴다. `혁신`, `새로운 시대`, `가치를 창출`, `완벽한 관리` 같은 설명 없는 수식은 추가하지 않는다.
- 사용자가 수정한 제목과 말투는 유지한다. 문구를 고칠 때는 의미를 넓히거나 구현 완료를 새로 주장하지 않는다.

`실제 구현 화면`, `예시 데이터`, `시연 화면`, `자료 기준`, `미리보기` 같은 제작용 설명을 화면에 덧붙이지 않는다. 상세 출처, 데이터 범위, 연동·검증 상태는 발표자 노트로 옮긴다. 시장의 `추정`, 가격·확보율 `가정`, 숫자의 기준 시점은 그 숫자를 이해하는 데 필요한 본문으로 짧게 남긴다. 작업 중인 기능을 향후 계획으로 나누지 않는다. 어댑터를 구현한 사실과 실제 API 성공을 검증한 사실은 노트에서 구분한다.

폰트 원본과 OFL 라이선스는 [fonts 폴더](assets/fonts/)에 함께 보관한다. 현재 Windows 사용자 폰트에도 등록했다. 다른 PC에서 수정할 때는 이 글꼴을 설치해야 같은 모양을 유지할 수 있다. [Pretendard 공식 배포](https://github.com/orioncactus/pretendard/releases/tag/v1.3.9)

## 픽토그램과 다이어그램

Lucide의 선형 아이콘을 기본으로 쓴다. 아이콘끼리 선 굵기와 실제 크기를 맞추고, 필요한 경우 청록 계열 원 안에 밝은 아이콘을 넣는다. 원은 항목을 묶는 용도로 쓴다.

| 내용 | 구성 |
| --- | --- |
| 업무 단계 | 픽토그램과 가로 화살표 |
| 시스템 구조 | 사용자가 보는 화면, 업무 모듈, 저장소와 AI의 연결 |
| 시장 범위 | 큰 원 안에 작은 원을 넣은 포함 관계 |
| 공개 판례 검색 | 기간 제한 없는 검색 건수를 큰 숫자로 표시 |
| 사례의 기간 | 큰 숫자와 단위 |

텍스트, 도형, 차트는 PPT에서 수정할 수 있도록 만든다. 전체 다이어그램을 이미지 한 장으로 굳히지 않는다. 중첩 원은 시장 범위의 포함 관계로 읽히게 하고, 면적 비례가 아니라는 점은 발표자 노트에 설명한다.

## 사진과 캡처

뉴스에는 실제 기사 제목이나 보도 화면을 사용한다. 매체와 날짜는 제목 근처에 짧게, 원문 링크와 해석 범위는 노트에 남긴다. 뉴스의 생성 이미지를 실제 사건 사진으로 소개하지 않는다.

가족 대화 캡처는 종중 소개 제목 아래에 배치한다. 캡처의 원본 비율과 내용을 유지한다. 대화 속 주장이나 지도 표시를 소유권, 매각 면적, 피해 규모가 확인된 자료로 바꾸어 표현하지 않는다.

문구가 사진 위에 겹치지 않도록 여백을 확보한다. 사진을 줄여서 내용을 알아볼 수 없다면 제목을 옮기거나 사진이 차지하는 면적을 늘린다.

## 기능 소개: 기기 목업과 큰 타이포

유스케이스는 기능마다 하나의 랜딩 화면처럼 만든다. 단순한 캡처와 설명문을 반복하지 않는다. 큰 문구 하나, 맥북이나 폰 목업 하나, 필요한 보조 문구만 남긴다. 연속해서 넘길 때 기능 소개가 한 장면씩 이어지는 느낌을 만든다. 타이포그래피 영상이나 애니메이션을 별도로 만들지는 않는다.

각 보조 문구 앞에는 내용과 맞는 선형 아이콘을 넣는다. 한 단어 대신 기능의 이점이 읽히는 짧은 서브 캐치프레이즈 2~3개를 사용한다. 아이콘의 왼쪽 기준선과 문구 시작점을 맞추고, 맥북 받침대 끝까지 포함해 겹치지 않게 배치한다. ‘횡령 걱정 NO’ 같은 무조건적인 보증 대신 증빙·변경 기록처럼 서비스가 제공하는 수단을 쓴다.

| 기능 | 큰 문구 | 화면 구성 |
| --- | --- | --- |
| 종중 홈 | 오늘 확인할 일. | 왼쪽 타이포, 오른쪽 맥북 |
| 설립 준비 | 첫 서류부터 빠짐없이. | 왼쪽 맥북, 오른쪽 서류·후보 키워드 |
| 회의 녹음 | 말한 내용을 회의록으로. | 짙은 푸른 청록, 큰 글자와 폰 |
| 문서 검색·초안 | 지난 회의도, 이번 초안도. | 위쪽 넓은 제목, 아래 맥북과 원문·버전·초안 |
| 총회·동의 | 누가, 어떤 안건에 동의했는지. | 왼쪽 폰, 오른쪽 세 줄 타이포 |
| 재산·등기 | 우리 종중의 땅 | 맥북의 필지 지도, 필지 확인·변경 알림 픽토그램 |
| 재산·회계 | 우리 가문의 재산, 내가 지킨다 | 청록 배경, 회계 화면을 넣은 맥북 |
| 법률·전문가 | 우리 가문 법률 전문가 | 맥북의 전문가 후보와 짧은 상담 키워드 |

기기 프레임은 사용자 템플릿의 306쪽 아이폰과 312쪽 맥북 이미지를 그대로 사용한다. 기능 화면은 실제 앱의 캡처다. 기기 이미지, 화면 캡처, 바깥 타이포를 각각 분리해 PPT에서 바꿀 수 있게 한다. 같은 목업 프레임을 반복 사용하되 좌우 배치, 화면 크기, 배경을 바꿔 리듬을 만든다.

휴대폰에는 실제 모바일 화면을 넣는다. **맥북 창은 819:514, 폰 창은 438:775**다. 브라우저를 각각 **1638×1028**, **438×775**로 설정해 다시 캡처한다. 새 캡처를 원본 비율 그대로 기기 창에 가득 채운다. 레터박스가 생기지 않는지 실제 렌더링과 이미지 배치 치수로 확인한다. 사진과 캡처의 글자나 수치를 합성해 구현된 것처럼 만들지 않는다.

시연 데이터와 가상 전문가 후보, 캡처 시점, 실제 연동 검증 여부는 발표자 노트에 남긴다. 기능 화면에 반복되는 상태 문구를 덧붙이지 않는다.

## Codex, AI와 구조를 보여주는 방식

Codex로 개발한 과정과 제품 내부의 AI 호출을 구분한다. 통화 STT와 PRD, 가상 종원, 코드, 검사, 비공개 배포는 파일과 작업 기록을 근거로 설명한다. 시장 파트 뒤 **Codex 활용** 한 페이지에 작업 개요와 자료 수집을 모은다. 자료를 하나씩 별도 숫자 페이지로 만들지 않는다.

- Codex 작업: 6분 45초 통화, PRD와 8개 유즈케이스, 가상 종원 10명, UI와 CLJS 구현, 단위 검사, 독립 UI 검수, 비공개 배포 기록.
- 자료 수집: 법령·판례·필지는 Codex 요약의 파일·검색 픽토그램으로 묶는다. 상세 건수와 출처는 노트에 보존한다. 필지 지도를 보는 제품 기능은 유스케이스에 배치한다.
- 구조: **Sites** 안의 웹 앱, 서버 API와 도메인 모듈을 나눈다. 조직·명부, 재산·등기, 회계, 회의·동의, 문서·버전, 법률·전문가, AI 작업, 변경·알림, 자원 정리를 실제 코드의 의미별 책임으로 표시한다. OpenAI·D1·R2 연결을 그리되 별도 마이크로서비스처럼 표현하지 않는다. MCP는 뒤의 For Agents에 둔다.
- AI: **Whisper / whisper-1, GPT-6 Luna / gpt-6-luna, GPT-6.1 Sol / gpt-6.1-sol**을 역할과 함께 보여준다. **Luna Decisions**의 모델·다음 작업 선택, **File Search**의 문서·버전별 근거 검색과 인용을 별도 항목으로 둔다. 사용자 요청에 따라 Responses·Structured Outputs는 슬라이드 화면에서 제외하고 상세 구현 노트에만 둔다.
- 개발 방식: **PRD, 페르소나, 모듈러 모놀리스(DDD), PBT**를 각각 요구사항·완료 조건, 역할별 정상·예외 시나리오, 업무 경계·공개 함수, 불변식·반례 재현으로 설명한다. 아래에는 문서 버전 보존·중복 응답 방지·잔액 합계 일치라는 실제 규칙을 둔다. 테스트 개수 대신 한 일을 보여준다.
- One More Thing: 제목은 **For Agents**다. **Skills, MCP, MCP Events**를 업무 절차, 조회·실행, 변경 알림으로 보여준다. 다음 페이지에 사용자 제공 로그인 화면을 추가한다. 로그인 화면 자체를 도구 실행·이벤트 수신 성공으로 확대 해석하지 않는다.

발표용 근거는 [구현 스냅샷](data/implementation-evidence-v7.json)에 남긴다. 원본 세션 전체나 비밀 설정값은 발표자료에 넣지 않는다. 구현이 바뀌면 화면과 상태 문구를 함께 갱신한다.

## TAM, SAM, SOM

사용자가 만든 중첩 원의 순서를 유지한다.

**TAM: 등록 종중 → SAM: 전담 관리 체계가 있는 종중 제외 → SOM: 3년 내 확보 목표**

‘사업형 종중’은 이 발표에서 **전담 인력과 관리 체계를 갖춘 종중**을 뜻한다. 임대료 수입이나 수익사업 여부만으로 제외하지 않는다. 임야, 농지, 대지, 건물 등 재산 종류도 제한하지 않는다.

### 계산 초안

| 항목 | 모수와 계산 | 연간 구독매출 환산 |
| --- | --- | --- |
| TAM | 등록 종중 237,071개 × 연 50만원 | 1,185.36억원 |
| SAM | 사업형 20% 제외 가정, 189,657개 × 연 50만원 | 948.29억원 |
| SOM | SAM의 1%를 3년 내 확보 가정, 1,897개 × 연 50만원 | 9.49억원 |

등록 종중 237,071개는 **2024년 6월 기준**의 등기법포럼 자료에 실린 국토교통부 조회 수치다. 모든 자연발생 종중이나 실제 구매 고객의 수는 아니다. [원문, 인쇄면 9쪽](https://ebook.kabl.kr/registrationforum/202409/11/)

사업형 종중의 전국 비중은 이번에 확인한 자료에서 집계하지 않는다. **20% 제외는 초안 가정**이다. 10%, 20%, 30% 제외 시나리오를 계산 파일에 함께 보존하고, 향후 종중 표본 조사로 바꾼다.

연 50만원도 명문가의 확정 요금이 아니다. 운영·관리 인접 서비스인 [ZUZU Fund Service](https://fundservice.zuzu.network/fund-pricing/)의 공개 요금을 참고한 계산 기준이다. VAT, 전문가 수임료, 일회성 설립비는 제외한다.

원 안에는 범위와 짧은 이름을, 옆에는 종중 수와 연간 금액을 놓는다. `연 구독매출 추정`, `연 50만원 가정`을 수치 가까이에 둔다. 등록 모수, 제외율, 구독료, 확보율을 섞어 하나의 확정 시장 통계처럼 표현하지 않는다. 자세한 출처와 계산은 발표자 노트와 [시장 계산 자료](data/market-estimate-v6.json)에 남긴다.

## 분쟁 사례와 판례 수치

뉴스 페이지 제목은 사용자 문구인 **다툼과 소송의 온상**을 쓴다. 세 기사 옆에는 **종손 지위, 임대차, 대표권**을 표시한다. 기사 거래대금은 별도 강조 숫자로 쓰지 않는다.

연도별 감소 막대그래프는 발표에서 삭제한다. **기간 제한 없는 공개 판례 검색 1,416건**만 큰 숫자로 남긴다. 이는 국가법령정보센터의 공개 판례 검색 결과 수이며, 전국 신규 분쟁이나 고유 사건 수가 아니다. 출처·조회일·중복 가능성은 발표자 노트와 [계산 자료](data/market-estimate-v6.json)에 남긴다. 연도별 원자료는 보관하되 다른 방향의 추세로 바꾸지 않는다.

판례 페이지 화면에는 제목, 검색 픽토그램, **1,416건**을 하나의 시각 묶음으로 배치한다. ‘기간 제한 없는 전체 검색’과 조회일은 화면에서 제거하고 노트에 보존한다.

이어받는 일 페이지에는 **과거의 유산, 오늘의 일상, 미래의 문제**만 남긴다. 아래의 공동재산·회의와 기록·인수인계 보조 문구는 삭제한다.

## 음성과 PDF

첫 장의 전화 버튼은 화면 중앙에 놓는다. 사용자 제공 M4A 원본을 PPT 패키지에 넣고 미디어 동작으로 연결한다. 다른 PC에서 사용할 수 있도록 Downloads의 절대경로나 외부 웹 주소를 연결하지 않는다.

함께 제공하는 PDF에는 클릭 영역의 Sound 동작과 22,050Hz·16비트·모노 PCM을 넣고, 원본 M4A도 파일 안에 첨부한다. 문서 하나로 전달할 수 있지만 오디오 동작 지원은 PDF 뷰어에 따라 다르다. 데스크톱 Acrobat 계열에서 사용할 형식이며 브라우저·모바일에서의 재생을 보장하지 않는다. 일반 PPT→PDF 내보내기는 이 오디오 동작을 옮기지 않으므로 제공한 PDF를 사용하거나 `export-pdf.mjs`로 다시 만든다. 실제 Acrobat 재생 여부는 구조·미디어 바이트 검증과 별도로 보고한다. [Adobe 재생 안내](https://helpx.adobe.com/acrobat/using/playing-video-audio-multimedia-formats.html)

## 수정 순서

사용자가 편집한 최신 PPT를 먼저 확인하고 복사본에서 작업한다. 사용자가 지운 문구나 슬라이드를 과거 생성본에서 다시 가져오지 않는다. 원본 이미지, 제목, 순서와 문구를 유지하면서 요청한 부분을 고친다.

내보낸 뒤에는 사진 배치, 중첩 원의 포함 관계, 그래프 값, 글자 잘림을 실제 렌더링으로 확인한다. 출처와 가정을 표시한 채로 최신 PPT와 미리보기를 함께 저장한다.
