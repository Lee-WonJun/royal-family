# 명문가 발표자료 디자인

## 기준

첫 초안의 종이색 배경과 깊은 청록을 기본으로 쓴다. 사용자가 v5에서 되돌린 도입부와 명문가 소개 화면을 기준으로 삼는다. 푸른 기운은 낮은 채도의 청록과 회청색으로 표현한다. v11은 v10에 남긴 24개 주석을 기준으로 구성과 문구를 수정한 자료다.

`Premium Cloud Widescreen Multicolored.pptx`는 픽토그램과 다이어그램의 참고 자료다. 원 안의 아이콘, 단계 연결, 포함 관계를 빌려 쓰되 템플릿의 무지개색과 회색 글씨를 전체 테마로 가져오지 않는다.

발표자가 설명한다. 슬라이드는 문장을 대신 읽어주는 화면보다 사진, 큰 숫자, 관계를 보여주는 그림에 가깝게 만든다.

## 발표와 IR의 리듬

발표는 **아버지와의 통화**로 시작한다. 개인 경험, 제품 기능, 시장 추정 뒤에 Codex 활용 파트를 둔다. **Codex 요약은 이 파트의 첫 페이지**다. 통화 전사, PRD·페르소나, 법령·판례·필지 자료 수집, UI·코드·배포, 테스트·UI 검수를 중심 Codex와 원형 픽토그램으로 연결한다. 사각형 조직도나 수치 나열 대신 한눈에 작업을 읽을 수 있는 원형 다이어그램을 쓴다.

Codex 뒤에는 서비스 구조, AI 처리 흐름, 하네스를 둔다. v13에는 하네스와 **One More Thing 사이에 페르소나 리뷰 한 페이지**를 추가한다. 사용자 제공 리뷰 6개를 실제 서비스의 후기처럼 **2열·3행 카드**에 담는다. 이름·별점·원문을 함께 보여주며, 본문의 표현과 점수는 바꾸지 않는다. 흰 카드와 큰 별점, 짧은 역할, 원문을 사용한다. 평균 4.5는 제공된 여섯 점수의 단순 평균이다. 긴 페르소나 설명은 노트에 보존한다. **Skills·MCP·MCP Events는 모두 One More Thing 뒤 한 페이지로 모은다.** 마무리는 앞에서 사용한 명문가 브랜드 페이지를 다시 보여준다. 별도의 `지금 / 다음` 장은 만들지 않는다. 전체 기능을 이번 구현 범위로 묶는다.

내용 화면은 왼쪽 정렬을 기본으로 쓴다. 질문, 실패 경험, 브랜드 공개, One More Thing에는 넓은 여백과 큰 글자를 쓴다. 같은 크기의 아이콘 원이나 카드 세 개를 매 장 반복하지 않는다. 하단의 두꺼운 회색 띠와 제작용 문구는 빼고 쪽수만 남긴다. 출처와 상세 조건은 발표자 노트에 둔다.

밝은 종이색과 짙은 청록 사이의 전환으로 장면을 구분한다. 기능 소개에는 푸른 청록 `#173F49`, 옅은 회청색 `#E2ECEE`를 사용할 수 있다. 화려한 그라데이션, 3D 장식, 의미 없는 강조색은 쓰지 않는다.

## 글자와 문구

- 본문은 **Pretendard Regular**, 큰 제목과 숫자는 **Pretendard Bold**를 쓴다. 한글과 숫자의 굵기와 비례를 맞춘다. 작은 설명까지 모두 두껍게 만들지 않는다. 명문가 브랜드명에만 **Noto Serif KR**를 쓴다. 기존 Noto Sans KR·Calibri Light 조합은 사용하지 않는다.
- 16:9 화면을 유지한다. 현재 PPT의 실제 크기는 10 × 5.625인치다.
- 일반 제목은 30~36pt, 기능 화면의 큰 문구는 38~47pt, 항목 이름은 18~24pt, 큰 수치는 60~100pt를 기준으로 잡는다. 슬라이드 크기는 유지하고 글자가 넘치면 문구나 배치를 먼저 고친다.
- 한 화면에서 전달할 내용은 하나로 정한다. 짧은 제목, 필요한 항목 이름, 숫자만 먼저 남긴다.
- `회의 녹음`, `동의 요청`, `재산 자료 비교`처럼 화면에 있는 일을 직접 쓴다. `혁신`, `새로운 시대`, `가치를 창출`, `완벽한 관리` 같은 설명 없는 수식은 추가하지 않는다.
- 사용자가 수정한 제목과 말투는 유지한다. 문구를 고칠 때는 의미를 넓히거나 구현 완료를 새로 주장하지 않는다.

`실제 구현 화면`, `예시 데이터`, `시연 화면`, `자료 기준`, `미리보기` 같은 제작용 설명을 화면에 덧붙이지 않는다. 상세 출처, 데이터 범위, 연동·검증 상태는 발표자 노트로 옮긴다. 시장의 `추정`, 가격·확보율 `가정`, 숫자의 기준 시점은 그 숫자를 이해하는 데 필요한 본문으로 짧게 남긴다. 작업 중인 기능을 향후 계획으로 나누지 않는다. 어댑터를 구현한 사실과 실제 API 성공을 검증한 사실은 노트에서 구분한다.

폰트 원본과 OFL 라이선스는 [fonts 폴더](assets/fonts/)에 함께 보관한다. 현재 Windows 사용자 폰트에도 등록했다. 다른 PC에서 수정할 때는 이 글꼴을 설치해야 같은 모양을 유지할 수 있다. [Pretendard 공식 배포](https://github.com/orioncactus/pretendard/releases/tag/v1.3.9)

## 픽토그램과 다이어그램

Lucide의 선형 아이콘을 기본으로 쓴다. 아이콘끼리 선 굵기와 실제 크기를 맞추고, 필요한 경우 청록 계열 원 안에 밝은 아이콘을 넣는다. 원은 항목을 묶는 용도로 쓴다.

| 내용 | 구성 |
| --- | --- |
| 업무 단계 | 픽토그램과 가로 화살표 |
| 시스템 구조 | 사용자가 보는 화면, 업무 모듈, 저장소와 AI의 연결 |
| 시장 범위 | 큰 원 안에 작은 원을 넣은 포함 관계 |
| 공개 판례 검색 | 기간 제한 없는 검색 건수를 큰 숫자로 표시 |
| 사례의 기간 | 큰 숫자와 단위 |

텍스트, 도형, 차트는 PPT에서 수정할 수 있도록 만든다. 전체 다이어그램을 이미지 한 장으로 굳히지 않는다. 중첩 원은 시장 범위의 포함 관계로 읽히게 하고, 면적 비례가 아니라는 점은 발표자 노트에 설명한다.

## 사진과 캡처

뉴스에는 실제 기사 제목이나 보도 화면을 사용한다. 매체와 날짜는 제목 근처에 짧게, 원문 링크와 해석 범위는 노트에 남긴다. 뉴스의 생성 이미지를 실제 사건 사진으로 소개하지 않는다.

가족 대화 캡처는 종중 소개 제목 아래에 배치한다. 캡처의 원본 비율과 내용을 유지한다. 대화 속 주장이나 지도 표시를 소유권, 매각 면적, 피해 규모가 확인된 자료로 바꾸어 표현하지 않는다.

문구가 사진 위에 겹치지 않도록 여백을 확보한다. 사진을 줄여서 내용을 알아볼 수 없다면 제목을 옮기거나 사진이 차지하는 면적을 늘린다.

## 기능 소개: 기기 목업과 큰 타이포

유스케이스는 기능마다 하나의 랜딩 화면처럼 만든다. 단순한 캡처와 설명문을 반복하지 않는다. 큰 문구 하나, 맥북이나 폰 목업 하나, 필요한 보조 문구만 남긴다. 연속해서 넘길 때 기능 소개가 한 장면씩 이어지는 느낌을 만든다. 타이포그래피 영상이나 애니메이션을 별도로 만들지는 않는다.

| 기능 | 큰 문구 | 화면 구성 |
| --- | --- | --- |
| 종중 홈 | 오늘 확인할 일. | 왼쪽 타이포, 오른쪽 맥북 |
| 설립 준비 | 첫 서류부터 빠짐없이. | 왼쪽 맥북, 오른쪽 서류·후보 키워드 |
| 회의 녹음 | 말한 내용을 회의록으로. | 짙은 푸른 청록, 큰 글자와 폰 |
| 문서 검색·초안 | 지난 회의도, 이번 초안도. | 위쪽 넓은 제목, 아래 맥북과 원문·버전·초안 |
| 총회·동의 | 누가, 어떤 안건에 동의했는지. | 왼쪽 폰, 오른쪽 세 줄 타이포 |
| 재산·등기 | 우리 종중의 땅 | 맥북의 필지 지도, 필지 확인·변경 알림 픽토그램 |
| 재산·회계 | 들어온 돈, 나간 돈. | 청록 배경, 회계 화면을 넣은 맥북 |
| 법률·전문가 | 우리 가문 법률 전문가 | 맥북의 전문가 후보와 짧은 상담 키워드 |

기기 프레임은 사용자 템플릿의 306쪽 아이폰과 312쪽 맥북 이미지를 그대로 사용한다. 기능 화면은 실제 앱의 캡처다. 기기 이미지, 화면 캡처, 바깥 타이포를 각각 분리해 PPT에서 바꿀 수 있게 한다. 같은 목업 프레임을 반복 사용하되 좌우 배치, 화면 크기, 배경을 바꿔 리듬을 만든다.

휴대폰에는 실제 모바일 화면을 넣는다. **맥북 창은 819:514, 폰 창은 438:775**다. 브라우저를 각각 **1638×1028**, **438×775**로 설정해 다시 캡처한다. 새 캡처를 원본 비율 그대로 기기 창에 가득 채운다. 레터박스가 생기지 않는지 실제 렌더링과 이미지 배치 치수로 확인한다. 사진과 캡처의 글자나 수치를 합성해 구현된 것처럼 만들지 않는다.

시연 데이터와 가상 전문가 후보, 캡처 시점, 실제 연동 검증 여부는 발표자 노트에 남긴다. 기능 화면에 반복되는 상태 문구를 덧붙이지 않는다.

## Codex, AI와 구조를 보여주는 방식

Codex로 개발한 과정과 제품 내부의 AI 호출을 구분한다. 통화 STT와 PRD, 가상 종원, 코드, 검사, 비공개 배포는 파일과 작업 기록을 근거로 설명한다. 시장 파트 뒤 **Codex 활용** 한 페이지에 작업 개요와 자료 수집을 모은다. 자료를 하나씩 별도 숫자 페이지로 만들지 않는다.

- Codex 작업: 6분 45초 통화, PRD와 8개 유즈케이스, 가상 종원 10명, UI와 CLJS 구현, 단위 검사, 독립 UI 검수, 비공개 배포 기록.
- 자료 수집: 법령·판례·필지는 Codex 요약의 파일·검색 픽토그램으로 묶는다. 상세 건수와 출처는 노트에 보존한다. 필지 지도를 보는 제품 기능은 유스케이스에 배치한다.
- 구조: **Sites** 안에 웹 화면과 CLJS 업무 모듈을 둔다. 화면에는 D1·R2·Vinext·Workers 세부 이름을 나열하지 않는다. MCP는 이 페이지에서 다루지 않는다.
- AI: **Whisper 전사, System 1 판단, 고지능 LLM 분석**의 세 단계다. System 1 아래에는 `모델 선택 · 매칭 추천`을 쓴다. 해당 용어는 빠른 판단의 역할을 뜻하며, 현재 Luna Decisions와 추천 흐름의 대응은 노트에 설명한다.
- 하네스: **PRD, 유스케이스, PBT, UI 검수**를 픽토그램과 키워드로 연결한다. PBT 아래에 `속성 기반 테스트`를 쓴다. 테스트 개수나 assertion 수를 주인공으로 만들지 않는다.
- One More Thing: **Skills, MCP, MCP Events**를 각각 업무 절차, 조회·실행, 변경 알림으로 보여준다. 도구 개수를 나열한 페이지는 삭제한다. 실제 ChatGPT 호출·수신의 검증 여부는 노트에서 구분한다.

발표용 근거는 [구현 스냅샷](data/implementation-evidence-v7.json)에 남긴다. 원본 세션 전체나 비밀 설정값은 발표자료에 넣지 않는다. 구현이 바뀌면 화면과 상태 문구를 함께 갱신한다.

## TAM, SAM, SOM

사용자가 만든 중첩 원의 순서를 유지한다.

**TAM: 등록 종중 → SAM: 전담 관리 체계가 있는 종중 제외 → SOM: 3년 내 확보 목표**

‘사업형 종중’은 이 발표에서 **전담 인력과 관리 체계를 갖춘 종중**을 뜻한다. 임대료 수입이나 수익사업 여부만으로 제외하지 않는다. 임야, 농지, 대지, 건물 등 재산 종류도 제한하지 않는다.

### 계산 초안

| 항목 | 모수와 계산 | 연간 구독매출 환산 |

| TAM | 등록 종중 237,071개 × 연 50만원 | 1,185.36억원 |
