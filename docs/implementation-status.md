## 실행한 검증

- CLJS 단위·PBT: 50개 테스트, 211개 assertion 통과. 기본 seed `20261009`, 속성당 100개 사례. 실제 외부 호출 0회.
- Node 어댑터 검사: 개발자 접근 4개, OpenAI fake 10개, Events 8개, PDF 1개 통과. Events의 HTTP 전송 변경 후 해당 8개를 다시 통과했다.
- TypeScript 검사와 CLJS/Vinext 배포 빌드 통과. UI·도메인 CLJS 경고 0개. Vite의 500 kB 초과 chunk 안내는 남아 있다.
- 강제 mock API E2E: **11개 시나리오, HTTP 요청 125개 통과**, 외부 provider 호출 0회. 문서·동의 버전, 회계 정정, 회의 상태 분리, 계층·인수인계, 토지·계약, 파일 원본, 7개 AI 작업, 상담·PDF, 개발자 잠금·MCP, 리셋·지연 결과·파일 정리를 확인했다. 초기 실행 기준은 `b0abd43895f2de65b35439c03601e7706cc75159`(121요청)이며, CLJS 정책 이관·전문가 매칭·PDF 보강 후 전용 DB에서 125요청으로 다시 통과했다. 후속 실행은 변경 중인 작업 트리였으며 결과에 변경 경로를 함께 남겼다.
- GPT-6.1 Sol 독립 화면 검수는 [검수 기록](../qa/ui-acceptance-2026-10-09.md)을 따른다. 과거 버전의 검토 버튼이 최신 버전을 변경할 수 있던 결함을 고쳤고, v1 읽기 전용·v2 검토 요청·v1 보존 반례를 재확인했다. AI 새 버전 반영, 회의·동의·인수인계 쓰기와 PDF 문장부호 수정 재검수도 통과했다. 추가 전문가 매칭의 후보 선택·후보 없음·정보 보완과 1440→768→360 질문 보존도 독립 PASS다. 마지막 안내 문구까지 확인한다.
- PDF 한글 폰트 누락을 실제 렌더링으로 발견해 전체 폰트 포함 방식으로 수정했다. 긴 한국어 문서의 3쪽 출력과 선택 원본 첨부·해시를 확인했다. 복사한 문장부호가 호환 문자로 바뀌는 추가 결함을 고쳤고 PDF의 실제 ToUnicode와 독립 pypdf 추출에서 날짜·자료 ID·근거를 대조했다.
- Impeccable 정적 검사 결과 0건. 이 결과가 실제 화면 검수를 대신하지 않는다.
- 세 서버 비밀값을 dist/generated 출력과 대조한 결과 3개 값 모두 노출 0건이다. 공개 fetch 호환성 설정도 배포용 wrangler.json에 포함됐다.

프롬프트·모델 정책·결과 검증·mock 생성은 서버 CLJS 모듈로 이관했다. 기존 fake 요청 본문·프롬프트·결과와 mock 7종의 동일성을 확인했다.

재현 스크립트는 `service/test/e2e-api.mjs`·`service/test/e2e-live-openai.mjs`다. 상세 로그와 화면은 Git 제외 경로 `qa/artifacts/`에 보관한다.

## 실제 OpenAI 호출

로컬 전용 검증 서버에서 사용자의 프로젝트 키를 서버에 주입하고 다음 사례를 실행했다. 결과·요청 ID·모델·사용량은 `qa/artifacts/live/openai-results.json`에 있다. 성공한 사례는 반복 호출하지 않았다.

| 사례 | 결과 | 확인 범위 |
| --- | --- | --- |
| 가상 한국어 회의 음성 | 성공, Whisper-1 1회 | 45.2초 합성 음성, 원문 전사·구간 시각·새 문서 버전 적용. 일부 고유명사 오인식은 남아 있어 원음 대조 필요 |
| 회의록 초안 | 성공, Luna Decisions + gpt-6-luna | 일정·전화 안내·미확인 금액·근거를 구조화. 실제 결의로 표현하지 않음 |
| 다음 검토 단계 | 성공, Luna Decisions | 미확인 견적에 대한 다음 행동 선택 |
| 가상 전문가 설명 | 성공, Luna Decisions + gpt-6-luna | 입력 후보와 조건 안에서 설명·미확인 사항 표시 |
| File Search | 수정 후 성공, Luna Decisions + gpt-6-luna | 입력 녹취 v2만 색인·검색, 미확인 견적과 원음 대조 필요를 근거 인용으로 반환. 이전 2회 권한 오류 기록 유지 |

실제 5개 대표 사례를 완료했다. 실패한 검색 2회를 포함해 모델 요청 총 10회, 이 중 Astra 0회다. 기록된 업무 provider 요청은 22회이며 별도 권한 진단용 읽기 요청은 이 수에 포함하지 않았다. Files·Vector Stores Write 권한 저장 후에도 프로젝트를 생략한 요청은 401이었고, `OpenAI-Project`를 명시한 동일 키는 200이었다. 서버 생성·검색·정리 경계에 프로젝트 설정을 추가해 실패 사례만 재검증했다. 검색의 임시 vector store와 파일 모두 삭제 완료를 확인했다. 새 전문가 매칭은 v3와 설명 입력을 보강한 v4에서 각각 성공했다. Luna Decisions가 가상 후보 2명 전체에서 박지훈을 선택하고 Luna로 이유를 작성했다. 각 3회, 총 6개의 추가 모델 요청이며 Astra는 없었다. v4에서는 이름과 선택 후보의 이유를 표시하고 의도적인 후보 제한을 자료 누락으로 오인한 문구가 사라졌다. 이 작업의 전체 모델 요청은 실패 사례 포함 16회이며 Astra 0회다. 실제 추출·법률 설명과 Sol 생성 경로는 이번 선택 사례에 포함하지 않았으며 fake 계약 검증만 통과했다. 모든 실제 호출 토글은 검증 후 OFF로 복원했다.

## 배포와 남은 연결

소유자 전용 [명문가 사이트](https://royal-family-demo.seeroe.chatgpt.site)를 최신 코드 배포가 한 차례 성공했다. 추가 CLJS 정책·전문가 매칭·PDF 수정본은 최종 갱신 준비 중이다. Sites runtime secret `AI_UNLOCK_CODE`, `OPENAI_API_KEY`, `MCP_ENCRYPTION_KEY`는 모두 비밀값으로 설정했고 기본 호출 모드는 mock이다. 현재 코드를 배포하기 전까지 기존 사이트를 최신 구현 검증으로 인용하지 않는다.

명문가 플러그인으로 실제 `get_clan_overview`를 호출해 가상 명부 10명과 회의·동의·확인 항목을 받았다. OAuth 도구 연결은 확인됐으며 최신 배포 뒤 다시 읽기를 확인한다. 남은 확인은 최신 Sites 배포와 ChatGPT Events 수신·응답이다. 외부 연결이 남은 동안 전체 완료나 해커톤 제출 완료로 기록하지 않는다.
