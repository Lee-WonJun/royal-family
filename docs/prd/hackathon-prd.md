# 명문가 해커톤 PRD

작성일: 2026-10-09 · 버전: 1.0 · 제품명: 명문가 · 저장소: Royal Family

이 문서는 해커톤에서 구현할 요구사항이다. 1차 서비스 코드와 mock 업무 규칙을 구현했으며, 실제 API·ChatGPT Events와 전체 제품 검증은 아직 완료되지 않았다. 현재 상태는 [구현 현황](../implementation-status.md)에서 구분한다.

## 목표와 사용자

명문가는 **종중의 설립 준비, 운영 관리, 법적 검토와 전문가 연결까지** 이어지는 서비스를 목표로 한다. 회장·총무는 흩어진 문서와 결정 과정을 정리하고, 종원은 본인에게 필요한 자료와 동의 요청을 확인한다. AI는 원문을 읽어 초안을 만들고 확인할 사항을 찾으며, 법무사·변호사에게 전달할 자료를 준비한다.

해커톤에서는 한 종중의 업무가 화면과 데이터로 이어지는 모습을 시연한다. 첫 사례는 전주이씨임영대군파종중과 공주시 태봉동 산41-1이다. 실제 명부·규약·거래·총회 자료를 확보한 것으로 가정하지 않는다. 기존 10개 [페르소나](../../qa/scenarios/hackathon-use-cases.md#personas)는 가상 사용자이며 실제 종원의 신원이나 자격을 나타내지 않는다.

제품의 사용자 유형은 회장·총무·검토자·일반 종원이다. **해커톤 앱은 가상 종원 10명의 시연 계정 선택으로 시작**한다. 각 버튼 아래에 권장 시나리오를 표시하고 선택한 업무 화면으로 이동한다. 현재 선택은 시나리오 진입점이며 모든 계정이 같은 시연 관리 기능을 사용한다. 실제 본인 인증·역할별 인증은 후속 범위다. 외부 전문가는 선택한 상담 자료만 전달받는 대상으로 설계한다.

## 문서 사용 순서

- 기능 범위와 완료 기준은 이 PRD를 따른다. 사용자의 이후 결정은 관련 문서에 함께 반영한다.
- [시스템 설계](../architecture/system-design.md)는 모듈·저장·AI·업무 상태를 정의한다.
- [MCP·skills 명세](../architecture/mcp-and-skills.md)는 외부 공개 기능과 이벤트를 정의한다.
- [테스트 전략](../architecture/testing.md)과 [QA 유즈케이스](../../qa/scenarios/hackathon-use-cases.md)는 검증 기준이다.
- `rawdata`의 PRD 초안과 발표 대본은 근거 자료다. 그 안의 P0·P1, 제품명 미정, 완료형 표현을 현재 구현 상태로 읽지 않는다.

| 최근 토지이동연혁 표시 | 2022-03-23 / 14,154.0㎡ / 분할되어 본번에 -13을 부함 |

조회일은 2026-10-09이며 표 안의 날짜는 원자료에 표시된 과거 이력이다. 면적 차이를 매매·불법 처분의 증거로 해석하지 않는다. 과거의 `림영` 표기를 원본에서 지우지 않는다. 최초 자료 등록은 기준값을 확보하는 작업이며 새로운 소유자 변동 알림을 만들지 않는다.

RF-03의 토지 화면은 OpenStreetMap 배경지도 위에 해당 PNU의 실제 경계를 표시한다. 기본 경계는 출처·조회 시점이 있는 저장 공공 자료이며, 옆의 재조회 버튼으로 K-GeoP 경계만 새로 조회한다. 재조회 실패는 기존 경계·시점을 보존하고 오류로 표시한다. 소유권 확인·소유자 자료 갱신과 구분한다. [좌표와 지도 연결 명세](../architecture/parcel-map.md)를 따른다.

## 화면과 업무 상태

| 화면 | 먼저 보여줄 내용 |
| --- | --- |
| 시작·설립 준비 | 원하는 업무, 준비된 서류, 추가 확인 항목, 법무사 후보 |
| 종중 홈 | 예정 총회, 내 동의 요청, 미검토 문서, 토지 확인 지연, 확인할 문제 |
| 명부·종원 계층 | 부모–자녀·세대·계통, 관계 확인 상태, 종원 상세, 연락 상태, 직책·권한, 수동 안내 기록 |
| 재산·계약·회계 | 토지 자료 출처와 시점, 연결 계약·거래·증빙, 결산 |
| 총회·동의 | 안건·자료 버전, 대상자, 안내·참석·위임·표결·별도 동의 현황 |
| 자료실·작성·검토 | 원본과 AI 초안, 근거, 미확인 값, 버전 차이, 승인·정정·PDF |
| 법률·문제 확인 | 공식 근거, 규약, 누락·불일치, 전문가 질문과 추천 후보 |
| 변경·연동 현황 | 토지 변화, 구독 상태, 전달 실패, ChatGPT 수신 확인 증거 |
| 톱니바퀴 설정 | 기능별 mock/실제 호출 토글, 연결 준비 여부, 전체 데이터 리셋 |

모든 화면은 모바일부터 반응형으로 설계한다. 360px에서는 한 열과 접을 수 있는 메뉴·설정 패널, 768px에서는 가용 폭에 맞는 분할, 1280px 이상에서는 사이드바와 목록·상세 배치를 사용한다. 넓은 표·지도는 해당 영역 안에서만 스크롤하고 페이지 전체의 가로 넘침은 막는다. 가로 회전·200% 확대에서도 주요 버튼을 가리지 않으며 입력·선택·문서 버전을 유지한다. 글자와 터치 영역은 고령 사용자가 읽고 누르기 쉽게 배치하고 상세 근거를 같은 흐름에서 열 수 있게 한다.

톱니바퀴는 PC의 옆 메뉴와 모바일의 접근 가능한 메뉴에 둔다. 설정을 열어도 작성 중인 입력은 유지한다. 기능별 준비 상태와 실제 호출의 실패를 보여주며 키 값은 화면에 표시하지 않는다. 전체 리셋은 시연 공간만 대상으로 하고 vaults·원자료·이미 실행된 외부 업무를 되돌리지 않는다.

동의 수집은 특정 문서 버전에 대한 응답 기록이다. 화면의 읽음·내부 확인·찬성 응답을 같은 상태로 합치지 않는다. 규약과 업무 유형이 미확인인 상태에서는 법적 결의 완료를 표시하지 않는다.

종원은 평면 명단뿐 아니라 가계 관계를 가진 계층으로 관리한다. 선택한 종원의 상위 세대·하위 세대를 펼쳐보고 같은 계통을 따라 상세 기록으로 이동할 수 있어야 한다. 세대·분파 표기는 확인한 자료가 있을 때만 등록하며 모르는 관계는 연결하지 않은 상태로 둔다. 회장·총무 같은 직책과 서비스 권한은 가계 계층과 별도 항목이다. 나이·성명·항렬만으로 관계나 종중원 자격을 자동 판정하지 않는다.

## 입력 준비와 범위의 한계

| 필요한 입력 | 현재 상태 / 처리 방침 |
| --- | --- |
| 전사 시연용 음성 | 저장소에 녹음 파일이 없다. 사용할 수 있는 녹음 또는 명시적인 시연 녹음을 준비한다. 인터뷰 전사만으로 실제 STT 호출을 시연했다고 하지 않는다. |
| 규약·명부·회의록·계약·회계 | 실제 자료는 미확보다. [QA 입력 명세](../../qa/scenarios/hackathon-use-cases.md#fixtures)에 따라 가상 자료를 준비한다. |
| 토지 비교 자료 | 공개 기준값은 위 조회 기록으로 고정한다. 소유자 변화 시연에는 명시적으로 모의 후속 자료를 쓴다. |
| 전문가 후보 | 기존 파트너 페르소나를 참고해 가상 추천 데이터를 준비한다. 실제 연락처·승소율·경력·수임 가능성을 만들어 넣지 않는다. |
| OpenAI·Sites·Events 접근 | 모델·키·잔액·Sites 권한·Work Cloud 플러그인 설치는 구현 단계에서 확인한다. 이 문서는 접근 가능성을 검증한 실행 보고서가 아니다. |

설립 관련 기능은 준비 업무를 분류하고 서류와 상담자료를 만드는 범위부터 시작한다. 종중 구성·운영 정비, 부동산등기용 등록, 토지 등기, 법인 설립을 하나의 절차로 합치지 않는다. 요청 유형을 확인할 수 없으면 담당 전문가에게 묻는 항목으로 남긴다.

법령 검색은 공식 원문과 등록한 규약을 근거로 한다. 민법 제275·276조는 초기 검색 자료이며, 개별 종중의 규약·대상자·안건에 따른 결론은 별도 검토가 필요하다. 2025다213795는 대표권 흠결과 준재심 요건에 관한 판결이므로 모든 총회 결의의 효력을 한 번에 판정하는 규칙으로 사용하지 않는다.

자동 발급·상시 등기 모니터링, 실제 외부 푸시·전문가 계약·법적 제출은 후속 구현이다. 미구현 연동은 설정에 ‘실제 연결 준비 필요’를 표시하며 토글만으로 동작한다고 하지 않는다. 개인정보 정리는 사용자 방침을 따르며 `rawdata`는 Git 추적·푸시 대상이다. 로컬 시크릿은 `vaults/<서비스>/.env`에 보관하고 Git·배포 소스에서 제외한다. 서버 실행·배포 시 필요한 값만 환경에 주입한다.

## 완료 판정과 측정

문서 작업은 RF-01–RF-22가 설계·QA에 연결되고, 8개 유즈케이스와 10개 페르소나의 검증 관점을 찾을 수 있으며, 링크와 출처·상태가 일치하면 완료다.

제품 데모 완료는 필수 구현·단위 테스트·빌드 후 mock E2E와 선택한 실제 연결 사례로 판정한다. 일반 회귀·반응형·토글·리셋 검증은 OpenAI를 호출하지 않는다. 실제 API와 ChatGPT 검증은 명시적으로 선택한 대표 사례에 한정하며 웹훅 2xx와 채팅 수신·응답을 따로 기록한다. 현재는 1차 구현 단계이며 전체 제품 완료를 판정하지 않았다.

실증 때는 자료 등록부터 초안·검토·PDF까지의 소요 시간, 누락·불일치 발견 내역, AI 처리 시간·사용량·비용, 동의 미응답 수, 이벤트 전달과 채팅 반응을 기록한다. 비교 기준을 측정하기 전에는 절감률·정확도·법적 효과를 수치로 주장하지 않는다.
