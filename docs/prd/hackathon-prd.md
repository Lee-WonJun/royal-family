# 명문가 해커톤 PRD

작성일: 2026-10-09 · 버전: 1.0 · 제품명: 명문가 · 저장소: Royal Family

이 문서는 해커톤에서 구현할 요구사항이다. 현재 완료된 것은 기획·설계 문서이며, 서비스 코드·API 연결·배포·제품 테스트는 아직 완료되지 않았다.

## 목표와 사용자

명문가는 **종중의 설립 준비, 운영 관리, 법적 검토와 전문가 연결까지** 이어지는 서비스를 목표로 한다. 회장·총무는 흩어진 문서와 결정 과정을 정리하고, 종원은 본인에게 필요한 자료와 동의 요청을 확인한다. AI는 원문을 읽어 초안을 만들고 확인할 사항을 찾으며, 법무사·변호사에게 전달할 자료를 준비한다.

해커톤에서는 한 종중의 업무가 화면과 데이터로 이어지는 모습을 시연한다. 첫 사례는 전주이씨임영대군파종중과 공주시 태봉동 산41-1이다. 실제 명부·규약·거래·총회 자료를 확보한 것으로 가정하지 않는다. 기존 10개 [페르소나](../../qa/scenarios/hackathon-use-cases.md#personas)는 가상 사용자이며 실제 종원의 신원이나 자격을 나타내지 않는다.

회장·총무·검토자·일반 종원은 서로 다른 권한을 갖는다. 앱 계정과 명부 항목을 분리해 미가입자도 안내 대상에 포함한다. 외부 전문가는 지정한 상담 자료만 전달받는 대상으로 설계한다.

## 문서 사용 순서

- 기능 범위와 완료 기준은 이 PRD를 따른다. 사용자의 이후 결정은 관련 문서에 함께 반영한다.
- [시스템 설계](../architecture/system-design.md)는 모듈·저장·AI·업무 상태를 정의한다.
- [MCP·skills 명세](../architecture/mcp-and-skills.md)는 외부 공개 기능과 이벤트를 정의한다.
- [테스트 전략](../architecture/testing.md)과 [QA 유즈케이스](../../qa/scenarios/hackathon-use-cases.md)는 검증 기준이다.
- `rawdata`의 PRD 초안과 발표 대본은 근거 자료다. 그 안의 P0·P1, 제품명 미정, 완료형 표현을 현재 구현 상태로 읽지 않는다.

## 해커톤 구현 수준

| 영역 | 구현 목표 |

| 관리 | 명부·토지·계약·회비·거래·회의는 샘플 데이터로 운영한다. 등록·연결·검토·응답·저장은 실제로 이어지고 재접속 후 유지된다. |

| 외부 업무 | 금융 이체, 자동 등기 발급, 전자서명, 전문가 접수는 mock이다. 실제 송금·서명·법적 제출을 수행하지 않는다. |
| MCP | 원격 도구와 이벤트 구독·서명 웹훅·ChatGPT 응답을 실제 연결한다. Sites 배포 성공과 플러그인 연결 성공을 별도로 확인한다. |
| skills | 자료 조회·총회 준비·변경 및 문제 확인 절차를 명세한다. 이번 문서 작업에서 실행용 SKILL.md는 만들지 않는다. |

초기 사이트는 소유자 제한을 기본값으로 삼는다. 시연 대상 확대는 별도 배포 작업에서 대상과 자료 범위를 정한다. 종중 단위 구독은 사업 가설이며 요금·시장 규모·시간 절감률은 아직 수치로 확정하지 않는다.

## 화면과 업무 상태

| 화면 | 먼저 보여줄 내용 |
| --- | --- |
| 시작·설립 준비 | 원하는 업무, 준비된 서류, 추가 확인 항목, 법무사 후보 |
| 종중 홈 | 예정 총회, 내 동의 요청, 미검토 문서, 토지 확인 지연, 확인할 문제 |
| 명부 | 계정 연결 여부, 연락 상태, 역할·권한, 수동 안내 기록 |
| 재산·계약·회계 | 토지 자료 출처와 시점, 연결 계약·거래·증빙, 결산 |
| 총회·동의 | 안건·자료 버전, 대상자, 안내·참석·위임·표결·별도 동의 현황 |
| 자료실·작성·검토 | 원본과 AI 초안, 근거, 미확인 값, 버전 차이, 승인·정정·PDF |
| 법률·문제 확인 | 공식 근거, 규약, 누락·불일치, 전문가 질문과 추천 후보 |
| 변경·연동 현황 | 토지 변화, 구독 상태, 전달 실패, ChatGPT 수신 확인 증거 |

모바일에서는 짧은 안내와 큰 글자, 분명한 행동 이름을 사용한다. 상세 근거는 같은 흐름에서 열 수 있게 한다. 알림 링크만으로 민감 자료나 다른 사람의 응답 권한을 넘기지 않는다.

동의 수집은 특정 문서 버전에 대한 응답 기록이다. 화면의 읽음·내부 확인·찬성 응답을 같은 상태로 합치지 않는다. 규약과 업무 유형이 미확인인 상태에서는 법적 결의 완료를 표시하지 않는다.

## 입력 준비와 범위의 한계

| 필요한 입력 | 현재 상태 / 처리 방침 |
| --- | --- |
| 전사 시연용 음성 | 저장소에 녹음 파일이 없다. 사용할 수 있는 녹음 또는 명시적인 시연 녹음을 준비한다. 인터뷰 전사만으로 실제 STT 호출을 시연했다고 하지 않는다. |
| 규약·명부·회의록·계약·회계 | 실제 자료는 미확보다. [QA 입력 명세](../../qa/scenarios/hackathon-use-cases.md#fixtures)에 따라 가상 자료를 준비한다. |
| 토지 비교 자료 | 공개 기준값은 위 조회 기록으로 고정한다. 소유자 변화 시연에는 명시적으로 모의 후속 자료를 쓴다. |
| 전문가 후보 | 기존 파트너 페르소나를 참고해 가상 추천 데이터를 준비한다. 실제 연락처·승소율·경력·수임 가능성을 만들어 넣지 않는다. |
| OpenAI·Sites·Events 접근 | 모델·키·잔액·Sites 권한·Work Cloud 플러그인 설치는 구현 단계에서 확인한다. 이 문서는 접근 가능성을 검증한 실행 보고서가 아니다. |

설립 관련 기능은 준비 업무를 분류하고 서류와 상담자료를 만드는 범위부터 시작한다. 종중 구성·운영 정비, 부동산등기용 등록, 토지 등기, 법인 설립을 하나의 절차로 합치지 않는다. 요청 유형을 확인할 수 없으면 담당 전문가에게 묻는 항목으로 남긴다.

법령 검색은 공식 원문과 등록한 규약을 근거로 한다. 민법 제275·276조는 초기 검색 자료이며, 개별 종중의 규약·대상자·안건에 따른 결론은 별도 검토가 필요하다. 2025다213795는 대표권 흠결과 준재심 요건에 관한 판결이므로 모든 총회 결의의 효력을 한 번에 판정하는 규칙으로 사용하지 않는다.

자동 발급·상시 등기 모니터링, 실제 외부 푸시·전문가 계약·법적 제출은 후속 구현이다. 이들 작업을 mock으로 보여주는 것과 완료된 외부 업무를 구분한다. 개인정보 정리는 사용자 방침을 따르며 `rawdata`는 Git 추적·푸시 대상이다. API 키·구독 서명 비밀키 등 운영 비밀은 원자료와 별도로 취급한다.

## 완료 판정과 측정

문서 작업은 RF-01–RF-18이 설계·QA에 연결되고, 8개 유즈케이스와 10개 페르소나의 검증 관점을 찾을 수 있으며, 링크와 출처·상태가 일치하면 완료다.

제품 데모 완료는 모든 필수 기능 구현, 단위 테스트와 빌드 통과 후 마지막 E2E에서 판정한다. 웹훅의 2xx 응답과 ChatGPT의 실제 수신·응답은 따로 기록한다. 현재 제품 완료 항목은 없다.

실증 때는 자료 등록부터 초안·검토·PDF까지의 소요 시간, 누락·불일치 발견 내역, AI 처리 시간·사용량·비용, 동의 미응답 수, 이벤트 전달과 채팅 반응을 기록한다. 비교 기준을 측정하기 전에는 절감률·정확도·법적 효과를 수치로 주장하지 않는다.
