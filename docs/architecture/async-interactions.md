# 비동기 작업과 화면 상태

2026-10-09 사용자 추가 요구. 기존 CandidateUi 분위기와 업무 흐름을 유지한다.

| 작업 | 대기 표시 | 완료·실패·중복 처리 |
| --- | --- | --- |
| 첫 계정·자료 조회 | 화면 구조를 유지하는 skeleton, `role=status` | 실패 원인과 다시 시도. 미조회 상태를 빈 자료로 표시하지 않음 |
| 저장·검토·동의·계정 변경 | 실행 버튼 spinner, 관련 쓰기 잠금. 600ms 이상이면 상단 작업 알림 | 성공 알림은 6초 뒤 닫힘. 오류는 사용자가 닫을 때까지 유지. 입력값 보존 |
| 원본 등록 | XHR 전송 바이트 기반 진행률. 전송 완료 뒤에는 별도 저장 중 표시 | 응답이 끊기면 같은 요청 키·원본으로 저장 확인. 0바이트·10MB 초과 파일은 전송 전 차단 |
| 후보·문제 조회 | 첫 조회 skeleton, 갱신 중 기존 결과 유지와 상태 표시 | 변경된 조건의 이전 요청 취소. 취소·오류·빈 결과 구분. 실패한 조건으로 상담 준비하지 않음 |
| 모달 저장·개발자 코드 | 제출 버튼 spinner, 처리 중 닫기·반복 제출 차단 | 실패 메시지를 모달 안에 표시. 저장 실패 때 폼을 닫지 않음 |
| 문서 편집 | 저장 버튼 spinner | 편집 시작 버전을 유지. 새 서버 버전이 와도 작성 중 텍스트를 바꾸지 않음 |

백그라운드 결과는 현재 계정 전환 시점과 데이터 generation·revision을 확인한 뒤 반영한다. 리셋 이전 응답이나 늦은 조회가 최신 자료를 덮어쓰지 않는다. 일반 JSON 요청은 30초, 파일 전송은 120초의 상한을 둔다. 서버가 이미 저장했을 가능성이 있는 타임아웃·네트워크 오류는 취소 성공으로 표현하지 않는다. 쓰기를 자동 재시도하지 않고 같은 idempotency key로 사용자가 저장 여부를 확인한다. 버전 충돌은 최신 자료 조회 후 사용자가 판단한다.

전체 화면을 막는 로딩 덮개는 사용하지 않는다. 메뉴와 읽기 동작은 유지하고 같은 원장을 수정하는 동작을 잠근다. 오류는 `role=alert`, 진행과 완료는 `role=status`, 관련 버튼과 영역에는 `aria-busy`를 사용한다. 동작 줄이기 설정에서는 회전·맥박 애니메이션을 멈춘다. 실제 비율을 모르는 AI 작업에 가짜 진행률을 붙이지 않는다.

업로드는 데이터 세대·요청 키·파일 SHA-256으로 안정된 R2 경로를 만든다. 응답 유실 뒤 같은 파일을 다시 보내도 같은 문서를 반환한다. 동시 요청이 이미 참조한 객체를 실패 처리에서 삭제하지 않는다. 이전 세대 객체 정리는 리셋 후 서버 정리 절차에서 처리한다.

검증: `royal.transport-test`에서 순서가 바뀐 snapshot, 응답 유실 후 거래 중복 방지, HTTP 실패, 시간 초과, 이전 조회 취소를 외부 호출 없이 검사한다. UI 시각 판정과 최종 E2E는 별도 완료 기록을 따른다.
