# 이벤트·정리 작업 실행

2026-10-09 구현. 프로토콜은 [MCP Events 계약](mcp-and-skills.md), 실제 연결 결과는 [구현 현황](../implementation-status.md)을 따른다. 구현·단위 검증과 실제 ChatGPT 수신은 별도다.

`royal.events`가 원자적인 변경·outbox·구독별 전달 생성과 모드·수명·권한·세대·필터를 검사한다. 서버는 D1에 저장한 lease를 얻은 전달만 실행한다. 본문과 eventId는 재시도에 유지하고 서명 시각만 바꾼다. 최대 3회, 각 요청 5초, 1초·2초와 작은 jitter의 대기를 사용한다. 중단된 전달은 실패로 남겨 명시적인 재시도로 복구한다.

`security.mjs`는 정규화한 인수·인증 주체·callback·이벤트로 구독 ID를 만들고 AES-GCM으로 서명 비밀값을 보관한다. master key는 `vaults/mcp/.env` 또는 Sites secret `MCP_ENCRYPTION_KEY`다. 공개 상태에는 callback 전체 URL·암호문·소유자 ID·본문·lease를 포함하지 않는다.

`network.mjs`는 HTTPS URL과 공개 목적지 주소를 검사한다. `transport-core.mjs`가 DNS의 공개 IP로 접속하고 TLS·Host에는 원래 hostname을 사용한다. redirect를 따라가지 않는다. 소켓 경계와 DNS를 주입한 테스트로 이 동작을 검사했다. 실제 Workers 목적지 제한은 live callback 검증에서 확인해야 한다.

구독 종료·권한 회수·만료·OFF·리셋은 후속 전달을 막는다. OFF 동안 생성한 사건은 ON으로 바꾸어도 전송하지 않는다. 로컬 앱에서 회수한 구독 권한을 매번 재검사한다. 플랫폼 자체 OAuth 연결 종료 통지는 별도로 제공되지 않으므로 수신 측의 410 또는 만료로 전달을 중지한다. 이를 플랫폼의 실시간 토큰 introspection으로 표현하지 않는다.

## 리셋 이후 파일 정리

원본과 PDF는 종중/데이터 세대별 R2에 저장한다. 리셋은 이전 세대 prefix만 정리 대상으로 추가하며 현재 세대를 삭제하지 않는다. 목록·삭제 성공 뒤 완료를 기록한다. 완료 후 늦게 도착한 이전 세대 업로드도 개별 객체를 정리한다.

File Search의 원격 파일·vector store는 생성 직후 서버 작업에 귀속된 자원으로 기록한다. 정상 종료 때 삭제하고, 실패·프로세스 중단·리셋 뒤 남은 자원은 정리 대기열에 보존한다. vector store에는 1일 만료도 설정한다. 정리 실패는 설정에서 확인하고 재시도한다. 시크릿·원자료·다른 종중 자원은 대상이 아니다. `RF_FORCE_MOCK=1`에서는 삭제 요청을 포함한 OpenAI 호출을 차단한다.

Workers의 제한된 후처리에서 한 번에 전달 2개와 정리 2개를 처리한다. API 요청·상태 조회가 있을 때 남은 작업을 이어가며 상주 워커나 예약된 무인 처리를 약속하지 않는다. 이미 전송한 요청을 취소하거나 수신 측의 처리 결과를 되돌린다고 표현하지 않는다.
