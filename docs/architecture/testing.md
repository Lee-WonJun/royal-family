# 테스트 전략

작성일: 2026-10-09 · 상태: 1차 단위·빌드·UI 검수 실행, 전체 E2E 미실행

테스트는 **단위 테스트와 E2E**로 나눈다. 단위 테스트는 업무 규칙과 공개 기능의 계약을 검증하고 개발 중 반복한다. E2E는 해커톤 필수 기능 구현·단위 테스트·빌드가 모두 완료된 뒤에만 실행한다. 1차 검증 결과와 미구현 범위는 [구현 현황](../implementation-status.md), 독립적인 화면 검수는 [UI 검수 기록](../../qa/ui-acceptance-2026-10-09.md)에 남겼다.

기능 범위는 [PRD](../prd/hackathon-prd.md), 행동과 기대 결과는 [QA 유즈케이스](../../qa/scenarios/hackathon-use-cases.md)를 기준으로 삼는다. 아래 항목을 정의한 사실과 테스트를 실행해 통과한 사실을 구분한다.

<a id="modes"></a>
## mock 기본과 선택적 실제 호출

| 실행 | 외부 연결 정책 |
| --- | --- |
| 단위·PBT | OpenAI·문자·등기·전문가·ChatGPT callback을 모두 mock/fake로 대체. 실제 네트워크 호출 0회 |
| 일반 E2E·반응형·설정·리셋 회귀 | 로컬 앱·저장은 실제로 구동하되 외부 연동은 mock. viewport나 반복 횟수 때문에 AI를 다시 호출하지 않음 |
| 최종 live E2E | 완료 게이트 이후 명시적으로 선택한 대표 사례만 실제 OpenAI·MCP/ChatGPT와 연결. 일반 테스트 명령·CI에서 자동 실행하지 않음 |

기본 테스트는 외부 실서비스 네트워크를 차단하고 예상하지 않은 요청이 생기면 실패시킨다. 로컬 앱과 시험 수신기는 허용한다. vaults의 실제 키를 읽지 않으며 환경에 키가 있거나 앱 설정에서 실제 호출을 켰더라도 자동으로 live가 되지 않는다. 토글 자체는 테스트용 어댑터 호출 기록으로 검증한다.

성공·부분 추출·근거 없음·색인 대기·스키마 오류·권한 거부·429·시간 초과를 고정 fixture로 준비한다. 민감정보를 제거한 실제 응답을 계약 fixture로 재사용할 수 있으나 비밀값·사용자 원문을 그대로 저장하지 않는다. mock fixture를 갱신하기 위해 매 테스트마다 API를 호출하지 않는다.

live 검증은 전사, 구조화/초안, 검색, Decisions, 실제 이벤트 생명주기를 덮는 최소 사례를 공유한다. 같은 결과로 여러 화면·검토 단계를 확인하고 이미 검증한 연결은 관련 모델·프롬프트·schema·어댑터 변경이나 실패가 있을 때만 재검증한다. 실패를 fake 성공으로 대체하지 않으며 실제 호출 증거와 mock 회귀 결과를 따로 남긴다.

<a id="unit"></a>
## 단위 테스트의 경계

등기부 목업 재조회는 `registry_test.cljs`에서 변경·동일값·반복 결과·실패·최초 기준 등록, 이전 등기 보존, 알림·outbox 원자적 생성, 읽음·권한·중복 요청·리셋을 검증한다. 조회 순서 PBT에서 소유자 차이와 알림 수가 일치하고 `charged_amount=0` 및 회계 무변경을 유지해야 한다. 실제 등기 서비스·결제·외부 발송은 호출하지 않는다.

CLJS의 `cljs.test`와 `test.check`를 사용한다. 공개된 업무 기능에 입력을 주고 결과·새 상태·발생 이벤트를 확인한다. 네트워크·DB·시각·ID·난수는 주입한 fake로 통제하고 실제 API 비용이나 외부 사이트 상태에 의존하지 않는다.

단위 범위에는 순수 규칙과 외부 어댑터의 입출력 계약을 포함한다. 예를 들어 webhook 서명은 고정한 키·시각·본문을 독립적인 검증기로 확인하고 한 바이트 변조가 거부되는지 본다. mock이 호출됐는지만 확인하거나 생성 함수와 같은 로직으로 기대값을 만들지 않는다.

한 내부 함수마다 테스트를 대응시키지 않는다. private 함수 이름·호출 순서·CSS 클래스·화면 전체 스냅샷·AI 문장 전체의 일치를 성공 조건으로 삼지 않는다. 사용자에게 약속한 상태나 결과가 바뀌면 테스트가 실패해야 한다.

| PBT-13 | 생성·수정·리셋·중복 리셋·지연 작업 완료 순서를 생성한다. 리셋 뒤 업무 데이터는 seed와 같고 모든 토글은 mock이다. 이전 세대 결과·이벤트가 복원되지 않으며 시크릿 저장소는 변경되지 않는다. | RF-20·21 |
| PBT-14 | 미연결 종원·복수 부모·여러 세대의 비순환 관계와 잘못된 연결을 생성한다. 자기 참조·순환·다른 종중 연결을 거부하고 조상·후손 조회가 유한한 고유 종원 집합을 반환한다. 관계 정정이 명부 ID·직책·권한·과거 회의 대상을 바꾸지 않는다. | RF-01·22 |

PBT-11은 모델의 법률 판단이나 문장의 진실성을 증명하는 테스트가 아니다. AI 응답을 검증하는 로컬 경계와 결과 상태의 규칙을 검사한다. 실제 AI 품질·근거 일치는 마지막 live E2E의 선택 사례로 확인한다. 권한의 역할 조합은 주입 문맥으로 검증하며 현재 앱에 역할별 로그인 화면을 요구하지 않는다.

### 생성기와 재현

정상 업무 입력 생성기와 잘못된 입력 생성기를 구분한다. 안정적인 ID, 여러 종중, 선택 항목 누락, 같은 시각, 중복 명령, 경계 금액, 제한된 권한과 서로 다른 문서 버전을 조합한다. 실제 규약의 정족수·종중원 자격을 모르는 상태에서 테스트용 규칙을 법률 규칙으로 일반화하지 않는다.

PBT 실행은 속성당 100개 사례를 기본값으로 두고 사례 수·seed를 옵션으로 받는다. 실패하면 seed, 속성 이름, 최초 입력, shrinking으로 얻은 최소 반례를 기록한다. 재현된 업무 결함은 해당 반례의 회귀 사례와 함께 고친다. 통과 후 이유 없이 횟수를 늘리거나 같은 전체 검사를 반복하지 않는다.

고정 예제는 빈 집합·권한 거부·미확인 값·과거 반례처럼 의도를 읽기 쉬운 경우에 사용한다. 생성기의 가능한 값만 다시 확인하는 테스트, 실패를 피하려고 업무 제약을 약하게 만드는 테스트는 추가하지 않는다.

<a id="e2e-gate"></a>
## E2E 실행 게이트

다음 조건을 모두 만족한 뒤 최종 E2E를 시작한다. 외부 시스템 검증을 다른 이름으로 바꿔 이 조건보다 먼저 전체 흐름을 반복 실행하지 않는다.

1. PRD RF-01–RF-22와 8개 유즈케이스의 필수 구현이 끝났다. 종원 계층, mock, 관리자 시작, 반응형, 기능 토글과 전체 리셋이 동작한다.
2. 단위 테스트·PBT와 CLJS/Vinext 배포 빌드가 통과했다.
3. 시연 음성·문서·가상 명부·후보·토지 비교 자료가 준비됐고 실제 자료와 구분된다.
4. 초기화 가능한 시연 데이터와 외부 호출 차단을 준비했다. 일반 mock E2E에는 OpenAI 키나 ChatGPT 연결이 필요하지 않다.

live E2E에만 추가로 vaults에서 서버에 주입할 키·모델 접근·Sites 배포·Work 플러그인, 선택한 사례와 실제 호출 비용 범위가 필요하다. mock 실패를 live 호출로 우회하거나 live 실패를 mock 성공으로 숨기지 않는다.

게이트가 미충족이면 필요한 조건을 기록하고 E2E를 보류한다. 부분 기능을 완성할 때마다 브라우저 전체 흐름을 실행하지 않는다. 개발 중에는 관련 단위 테스트·정적 검사·빌드로 검증한다.

일반 E2E는 mock 어댑터를 사용하는 웹 자동화로, live E2E는 필요한 실제 API·Work 채팅 확인으로 구성한다. 웹 자동화는 Playwright를 기준으로 접근 가능한 역할·레이블·안정적인 테스트 식별자를 사용한다. 고정 sleep 대신 상태 변화와 응답을 기다린다. ChatGPT 수신·응답은 지원되는 연결 도구나 확인한 채팅 증거로 기록한다.

## 최종 검증 항목

| 흐름 | 최종 E2E에서 확인할 결과 |
| --- | --- |
| 설립 준비·법무사 추천 | 준비 문서·부족한 항목·조건별 후보가 이어지고 가상 후보임이 명확하다. |
| 음성·기존 문서 | 일반 회귀는 전사·추출·검색 fixture의 처리와 검토 흐름을 확인한다. 실제 품질은 live 대표 사례에서만 원문과 대조한다. |
| 총회·회계·자동작성 | 명부·계약·거래·참석·위임·안건에서 문서·결산으로 이어지고 저장 상태가 재접속 후 유지된다. |
| 동의·검토·PDF | 대상 종원·기록한 관리자·시연 표시·버전이 맞고 거절·철회·기한·재요청·출력이 동작한다. |
| 법률·문제·변호사 | 근거·미확인 항목·조건별 후보·상담자료를 mock으로 검증하고 live 사례에서 실제 검색·설명 품질을 확인한다. |
| 토지·Events | 일반 회귀는 비교·outbox·로컬 수신기로 검증한다. live 대표 흐름만 실제 callback·Work 수신·응답·해지까지 확인한다. |
| 오류·권한 | OpenAI 실패·색인 미완료·다른 종중 접근·파일 내보내기·권한 회수·서명 오류가 정상 성공과 구분된다. |

| 반응형 | 360·768·1280·1440px, 가로 회전·200% 확대에서 읽기·작성·동의 기록·설정·리셋이 가능하다. 페이지 넘침·겹침·입력 유실이 없다. 모든 경우 mock 사용 |
| 종원 계층 | 상위·하위 세대와 미연결 종원을 계층·목록에서 찾고 상세로 이동한다. 관계 정정·잘못된 연결 거부·리셋 복원·좁은 화면 탐색을 mock으로 검증한다. |

고령 사용자 관점은 큰 글자·모바일 핵심 동작·출력물 가독성으로 검토한다. 기존 페르소나를 이용한 시나리오 검토를 실제 사용자 실험으로 표현하지 않는다. 법률 답변은 인용·출처·질문과의 관련성을 확인하며 전문가 검토를 수행했다고 기록하지 않는다.

실패 시 해당 원인을 수정하고 관련 단위 테스트와 영향받은 E2E 시나리오를 다시 실행한다. 이미 통과한 다른 전체 흐름은 새 변경·실패·미해결 우려가 있을 때만 반복한다.

## 명령과 결과 기록

현재 `test:unit`, `test:access`, `test:openai`, `test:events`, `test:pdf`, `typecheck`, `cljs:build`, `build`, `test:e2e`, `test:e2e:live`가 있다. 일반 단위 검사와 E2E는 fake 또는 강제 mock을 사용한다. E2E 두 모드는 완료 게이트 이후에만 실행하며 실제 API 검증은 명시적인 환경 변수와 전용 서버가 필요하다. 명령·전용 저장소·호출 상한은 [service/README.md](../../service/README.md), 실행 증거는 [구현 현황](../implementation-status.md)을 따른다. 기본 테스트·CI가 실제 API를 암묵적으로 호출하지 않는다.

제품 테스트 결과는 commit, mock/live 구분, 기능 토글·데이터 세대, 환경·모델, fixture 버전, 시나리오·속성 ID, 명령·seed·결과·증거를 기록한다. mock 실행은 실제 외부 호출이 0회였는지 확인한다. live는 호출 ID·시간·사용량을, 이벤트는 eventId·subscriptionId·전달·채팅 반응을 연결한다. vaults의 비밀값과 불필요한 원문 개인정보는 증거에 넣지 않는다.

이번 문서 작업의 검증은 Markdown 링크·앵커, RF–설계–시나리오 연결, 8개 유즈케이스·10명 페르소나 포함 여부, 출처와 현재 상태의 일관성, AGENTS 분량, 원자료 보존, diff 확인까지다. 이를 제품 단위 테스트·E2E 통과로 표기하지 않는다.
