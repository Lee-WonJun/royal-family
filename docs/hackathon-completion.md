# 해커톤 제출 준비

2026-10-09 사용자 요청: 비동기 UX와 실제 OpenAI 연결을 포함해 제출 가능한 완성본까지 진행한다. `System oneshot` 표현은 사용자의 정정에 따라 **Luna와 Decisions**로 해석한다. 생성 모델은 **Luna Decisions가 `gpt-6-luna`와 `gpt-6.1-sol` 중 선택**한다. Astra는 사용자의 명시적 요청으로 제외한다. 녹음 전사는 `whisper-1`을 사용하며 모델의 입력 형식과 기능을 맞춘다. 라우팅 실패를 임의 모델 선택으로 우회하지 않는다.

## 완료 순서

1. 요청 상태·진행·실패·중복 방지와 입력 보존.
2. 서버 OpenAI 어댑터, 작업 상태 저장, Whisper·추출·File Search·초안·Decisions, 실행 증거와 검토 흐름.
3. PRD 필수 업무의 미완료 부분과 서비스 skills·MCP Events 구현.
4. 단위·PBT·보안·빌드 후 mock E2E. 선택한 소수 실제 API·ChatGPT 연결 사례 검증.
5. GPT-6.1 Sol 독립 UI 합격, 커밋·푸시·Sites 배포, 시연 순서와 제출 자료의 구현 상태 정합성.

현재 진행 기록은 [구현 현황](implementation-status.md)에 반영한다. 미연결 API, 외부 서비스 승인, 실제 채팅 수신 증거가 남아 있으면 완료로 기록하지 않는다. 제출 준비는 사용자를 대신한 법적 동의·서명·최종 제출을 뜻하지 않는다.

기능별 실제 호출은 개발자 코드와 ON 상태를 확인한다. 기본·일반 회귀 테스트는 mock이며 실제 실패를 mock 성공으로 바꾸지 않는다. 시크릿은 `vaults`와 서버 환경에만 둔다. 원자료와 다른 동시 작업은 보존한다.


## 시연 순서

1. 가상 총무를 선택하고 홈에서 확인할 업무를 살핀다. 명부 계층에서 상위·하위와 미연결 종원을 확인한다.
2. 회의 기록에서 원본과 현재 버전을 열고 초안·근거·미확인 항목을 본다. 새 버전을 만든 뒤 과거 버전이 읽기 전용으로 남는 것을 확인한다.
3. 총회에서 전화 안내·참석 예정·실제 참석·위임·표결이 서로 독립적임을 보여 준다. 문서 버전별 동의 기록을 확인한다.
4. 재산에서 실제 필지 경계와 **목업 등기 재조회**를 구분해 설명한다. 동일값·소유자 변경·조회 실패를 비교한다. 회계 정정은 원거래와 정정 사유를 보존한다.
5. 법률·설립 화면에서 공식 근거와 미확인 사항, 가상 후보 조건, 상담에 포함할 자료 범위를 확인한다.
6. 선택 버전만 PDF로 내보내고 한글 본문·근거·첨부 범위를 확인한다.
7. 실제 AI 시연이 필요할 때만 개발자 코드를 입력하고 해당 기능을 ON한다. 작업 상태·실행 모델·원문 근거·실패를 보여 준 뒤 OFF로 돌린다. File Search는 선택 버전만 검색한 실제 성공 사례를 재사용할 수 있다.
8. 실제 ChatGPT 연결이 확인된 경우에만 도구 호출과 이벤트 수신·응답을 별도로 보여 준다. 앱의 outbox 또는 2xx 기록만으로 채팅 반응을 대체하지 않는다.

## 제출 전 확인

- [구현 현황](implementation-status.md)의 실제 검증 상태와 발표 문구를 맞춘다. 개인 프로젝트·가상 후보·시연 응답을 실제 회사 성과나 사용자 동의로 소개하지 않는다.
- 심사자가 사용할 접근 방식은 현재 소유자 전용 Sites 설정과 구분해 정한다. 공개 범위 확대는 별도 사용자 결정이다.
- 원자료는 원본으로 유지하고 시크릿은 코드·발표·첨부에 포함하지 않는다.
- 실제 수임·등기 발급·법적 유효성·전문가 검토를 수행했다고 주장하지 않는다.
- 대회 양식 업로드·동의·서명·최종 제출은 이 구현 작업에 포함하지 않는다.
